# 粘贴 / 拖入到焦点卡换图要等多久（改前改后实测）

> 读者：维护者，以及以后改上传流程的 AI。问题来自 [TODO](../TODO.md)「粘贴 / 拖入后、焦点卡换成新图之前没有任何反馈」，维护者选了「一动手就进队列」那一档。

## 怎么量

- 正式版构建（`npx tauri build --no-bundle`），Windows 10，本机；便携隔离库，图床接本机假 WebDAV（上传立刻成功），关自动复制。开发版的 Rust 依赖不开优化，压缩慢很多，不用它量。
- 从触发到首页焦点卡出现这张图的文件名（多张时批量卡写出「正在上传 N 张」）为止：页面里先挂 `MutationObserver`，再记开始时刻、触发。拖放用 `plugin:event|emit_to` 发 `tauri://drag-drop`，粘贴在页面里派发 Ctrl+V 的 `keydown`，剪贴板用 PowerShell 放图（测前存下维护者的剪贴板文字，测完原样写回）。每项 3 次取中位数，10 张那项跑 2 次。做法细节见 [testing-guide.md](../reference/guides/testing-guide.md)「真机走查」。
- 测试图：截图样 PNG（1920×1080 0.20 MB、3840×2160 0.88 MB）、4K 照片类截图 PNG（4.88 MB）、1366×768 小 JPEG（0.04 MB）、1200 万像素照片 JPEG（4000×3000 3.89 MB）。压缩用默认方案（质量 80、2 MB 以下只去 EXIF）。

## 结果

| 情况 | 改前·不开压缩 | 改前·开压缩 | 改后·不开压缩 | 改后·开压缩 |
|------|------|------|------|------|
| 拖入 1 张（各种大小） | 0.05 秒 | 小图 0.08–0.19 秒；4K 照片类 PNG 0.83 秒；1200 万像素照片 2.38 秒 | 0.01 秒 | 0.01 秒 |
| 一次拖入 10 张 1200 万像素照片 | 0.06–0.18 秒 | 10.4–10.6 秒 | 0.01–0.23 秒 | 0.02 秒 |
| 粘贴 1080p 截图 | 0.13 秒 | 0.15 秒 | 0.04 秒 | 0.04 秒 |
| 粘贴 4K 照片类截图 | 0.42 秒 | 1.12 秒 | 0.14 秒 | 0.15 秒 |

改后粘贴第一次偶有 0.14–0.37 秒（之后都在 0.04 秒上下），中位数不受影响。改后跑的 84 次上传全部成功、记录都有可用链接；这一轮压缩产生的临时副本全部删掉了（同一天修的「压缩临时文件在 Windows 上从不删除」）。

## 时间花在哪（改前，直接调对应命令单独计时）

- 压缩：1200 万像素照片 2.5–2.7 秒，4K 照片类 PNG 0.74–0.80 秒；2 MB 以下只去 EXIF：小 JPEG 约 0.14 秒、4K 截图 PNG 约 0.06 秒。多张时按每 3 张一组压，整批压完才进队列，所以 10 张要 10 秒多。
- 读剪贴板：判断有没有图要把整张图读出来（4K 0.09–0.14 秒），再读一遍存成 PNG（4K 0.18–0.28 秒）。
- 联网检测 0.03–0.12 秒；网络不通时按代码最多等 1.5 秒（没量）。读尺寸 1–11 毫秒。

## 改了什么

- 拖入、粘贴、选文件后图先进队列，焦点卡 / 批量卡当场换成这几张；联网检测、读尺寸、压缩都算「上传中」（进度条停在起点，批量卡的格子写「等待中」）。网络不通时把已进队列的图标成失败（说法不变）；准备时出了意外、一直没开始传的标成「准备上传时出错」，能重试。
- Windows 上判断「剪贴板有没有图」只问系统有没有图片格式（PNG 或 CF_DIBV5，与 arboard 读图的判断一致），不再把整张图读出来；托盘每次剪贴板变化时的检查也跟着省下。

## 没覆盖的

- 粘贴仍要先把剪贴板里的图存成文件才能进队列：4K 照片类截图约 0.14 秒，在 300 毫秒以内。
- macOS / Linux 没量（「有没有图」在那两个系统上仍按读一遍图判断）。
