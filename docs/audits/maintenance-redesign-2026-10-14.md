# 维护页（链接检测 / 文档修复 / 补充备份）体验改版与验收

> 验收口径：第一性原理（每个页面先回答用户的那个问题）、打开就知道怎么用（顶部一句结论 + 一个主按钮，复杂选项收起来、需要时找得到）、挑剔用户（文案说人话、状态不撒谎、操作有反馈）。做不好的功能宁可不要。

## 三页共用的骨架

- **顶部结论卡**（`link-check/common/SummaryCard.vue`）：一句话说清现在怎么样，旁边放这一刻最该点的按钮。没有结果可看时（没检查过 / 没选文件）居中放大，页面上只剩这一件事。
- **下面是清单**；不常用的操作收进卡片或行上的「⋯」，高级筛选收进「更多选项」。
- **该提示时才提示**：用一行字把用户引到另外两页（链接检测发现失效备份 → 文档修复；部分图只有一份 → 补充备份）。

## 每个页面要回答的问题

| 页面 | 用户的问题 | 回答方式 |
|------|-----------|---------|
| 链接检测 | 我的图还能不能打开？打不开的能不能救？ | 一张图一行；结论卡「N 张图片打不开」+「把 N 张改用备份」；行上一句白话（「微博上的图已不存在，京东上的备份能用」）+ 至多一个按钮（改用 X / 重试） |
| 文档修复 | 文档里哪些图打不开，会被换成什么？ | 结论卡「N 张图片打不开」+「修复 N 张」；按文档分组，每行写「→ 图床」的替换来源（可逐行改）；修好的行只说「已换成 X」，文档标题说清剩下的是没备份还是没写进去 |
| 补充备份 | 我的图有没有备份？没备份的帮我多存一份 | 先选「备份到哪」，来源默认全部图床；来源、上传时间、副本数收进「更多选项」；做完一句结论 +「重试失败的」 |

## 决定与理由

### 链接检测

- **按图片一行**：用户要的答案是「这张图还能不能看」；一张图按图床拆成几行，得自己拼。移除记录仍精准到（图片, 图床），只移除打不开的那几份，能打开的留着。
- **只留「有问题 / 全部」**：「失效 / 超时 / 可疑」由每行那句白话交代，列表按「能改用备份 / 打不开 / 可能受限 / 备份失效」分段。没问题时列表自动显示全部，用户手动切过就照用户的。
- **不做点行多选**：点行会被选中，用户发现不了；真正要的批量操作（只重查有问题的、导出、清理找不回的图片）放在结论卡的「⋯」。
- **「找不回」只认 404 / 410**：清理记录会删数据，超时、拒绝访问这类可能是暂时的，不算。
- **检查完不弹 toast**：结论卡已经换成新结论，再弹一次是重复反馈。检查中结论卡报「预计还要 N 分钟」，卡在慢图床时直说在等，不报不可信的时间。
- **改用备份不弹确认**：随时能改回、什么都不删；逐张切换，toast 如实报改成了几张。
- **移除失效的链接先提醒文档修复**：这张图还有能打开的一份时，文档里写的多半就是那条打不开的旧链接，文档修复靠它在记录里找到备份，删了就对不上。所以这个操作留在行「⋯」里，确认框写明后果、建议先修文档；整张图都打不开时本来没有备份可换，不提醒。
- **重试没变化也回一句**：单行重试结果没变时，按钮位置停一下「还是打不开」，免得用户以为没点上又连点。

### 文档修复

- **顶部结论卡**：一句话（「4 张图片打不开」「已修复 3 张图片」）+ 这一刻该点的按钮（修复 N 张 / 完成 / 撤销）；修改前自动备份、改完可撤销，所以不弹确认框，卡上写明「修改前会自动备份原文件」。
- **不弹策略框**：替换来源在扫描结束时就按「已存首选 → 否则最快」定好并显示在列表上，可逐行换、可「以后优先用 X，应用到全部」。
- **不做筛选标签**：列表只列打不开的图、按文档分组，能不能修看每行右边（「→ 图床」或「无可用备份」）；「全部 / 能修 / 要手动」只是把同一份信息再切一遍。
- **两个选项收进「选项」**：包含子文件夹、包含代码块里的图片大多数人用不到；改过默认值会写在「选项」后面，免得忘了。
- **写入失败说人话**：EACCES / EPERM 说「没有写入权限」，EBUSY 说「文件被其他程序占用」，ENOENT 说「文件找不到了」；系统错误码不上卡片。
- **修完的标签说剩下什么**：修好的行只说「已换成 X」，不再叠「已修复」；文档标题报「已修复 N 张」「N 张没有备份」「N 张没修好」，不说「已修复 0 / 2」这种像失败的话。

### 补充备份

- **改名「补充备份」**：它只复制、不删除，叫「迁移」会让人以为原图会被删掉。
- **先选备份到哪**：目标是用户唯一必须做的决定；来源默认全部图床，不用先勾。来源、上传时间、副本数这类细分收进「更多选项」。
- **做完只留一句结论**：成功几张、失败几张（给「重试失败的」）、本来就有几张；不再并排四个按钮。
- 不做自定义天数、份数输入：预设档（最近 7 天 / 30 天 / 3 个月 / 1 年；只有 1 份 / 不超过 2 份 / 不超过 3 份）够用，输入框会把「更多选项」变成一张表单。筛选只活在这次打开的页面里，没有旧的自定义值要迁移。

### 通用

- **状态说白话**：「502」「403」说成「图床出故障了」「拒绝访问」，状态码与原因留在悬停提示。
- **认图靠缩略图**：文件名多是 `clipboard_image_…`，没有缩略图认不出是哪张；打不开的图用它在其他图床的可用副本当预览。
- **「删除」叫「移除记录」**：它只改 PicNexus 自己的记录，确认框写明图床上的文件不受影响。
- **已删除的存储配置**显示为「WebDAV（已删除）」而不是随机 ID；没查配置（接线漏了）时仍显示 ID，便于排查。
- **量词统一**：图片说「张」，链接说「个」；回执和确认框用同一个单位（确认「清理 2 张」，回执「已从记录中移除 2 张图片」）。
- **列表预留滚动条位置**：链接检测、文档修复、备份进度三个列表变长变短时，右侧按钮不跳；补充备份的设置页不预留，否则有些窗口宽度下图床卡片一行少放一个，「添加图床」单独掉到第二行。

不做标签页上的问题数角标：进入链接检测，结论卡第一句就报了数。

## 验收记录

- 真机：Tauri 开发版 + WebView2 调试端口，用真实历史库（12 张图 / 17 条链接）走查三页亮暗两色；文档修复用临时目录里的测试文档实跑（逐行改来源后写入文件内容已核对，部分失败、全部正常两种结局都看过）；批量迁移不在真实账号上执行，进行中 / 完成态用视觉测试夹具核对。
- 自动化：单元测试全部通过；新增 / 改动的断言都先改坏被测代码确认会红；`npm run ci:prepush` 通过；e2e 冒烟（Chromium）8/8；三页视觉基准图已按新设计重录并复跑通过。
- 修掉的缺陷：检测完成后列表行停在「未检测」（单行组件只拿行引用，原地改写不刷新，已加回归测试）；部分失败时写入失败的行仍显示可点的「→ 图床」；需手动行多一个按钮把整列推歪。
- 第二轮（按图片重做）：链接检测改成一张图一行 + 结论卡一键改用备份，补充备份改名重排，文档修复改成结论卡。自动化：`npm run ci:prepush`、单元测试、e2e 冒烟、布局探针、视觉回归全部通过；新增断言都先改坏被测代码确认会红。修掉的缺陷：CSV 的检查时间列一直是空的；没来得及处理的图被报成「本来就有」（卡片和报告都错）；部分成功的图在卡片和列表里数字对不上；「最近打开」没有记录时仍显示空标题；补充备份的筛选徽标看不懂、副本数筛选的字面和实际查询不符；检查完重复弹提示；取消提示提到一个不存在的按钮；修复卡片直接显示 EACCES；修好的行「已修复」和「已换成」叠在一起。
- 第二轮真机走查：Tauri 开发版 + WebView2 调试端口，portable 隔离数据（12 张造的图 + 本机假图床，回 200 / 404 / 502 / 403 / 超时 / 302）。链接检测走完检查、改用备份、清理找不回的、移除失效链接、单行重试、深色；文档修复用临时文档实跑修复和撤销，文件内容逐字节核对；补充备份只看了没配图床时的引导（取原图那步会拦本机地址，跑不出成功流程，没跑）。修掉的缺陷：清理后提示「已删除 3 条记录」（用词、单位都和确认框对不上）；「1分钟前」少空格；移除失效链接后文档修复认不出旧链接（改为确认框提醒）；重试结果没变时没有回话；文档标题「已修复 0 / 2」像失败；列表出现滚动条时按钮跳动；链接检测基准图还停在旧标签「批量迁移」（1% 像素容差掩盖了）；部分失败截图的测试数据自相矛盾；删掉已无人调用的单条移除函数。自动化同上，全部通过。
