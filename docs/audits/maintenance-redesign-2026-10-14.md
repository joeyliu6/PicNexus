# 维护页（链接检测 / 文档修复 / 批量迁移）体验改版与验收

> 2026-10-14。验收口径：第一性原理（每个页面先回答用户的那个问题）、苹果式设计（层级清楚、所见即所得、能撤销就不弹确认）、挑剔用户（文案说人话、状态不撒谎、操作有反馈）。

## 每个页面要回答的问题

| 页面 | 用户的问题 | 改版后的回答方式 |
|------|-----------|-----------------|
| 链接检测 | 我的图还能不能看？坏的那份要不要紧？ | 每行缩略图 + 白话状态；坏链接旁边写「其他图床正常 / 无备份」；坏的是主链接且有备份时给「改用 X」 |
| 文档修复 | 文档里哪些图打不开，会被换成什么？ | 每行显示「→ 图床」的替换来源（可逐行改），点「修复 N 处」直接改，修好的行变成「已修复 · 已换成 X」 |
| 批量迁移 | 要把哪些图复制到哪里，会不会删原图？ | 目标卡片带勾选圈和「N 张待备份 / 已全部有备份 / 连接异常」；按钮写「开始补传备份」，提示「只复制、不删除」；结束后一句结论 |

## 决定与理由

- **状态说白话**：「502」「403」改成「图床故障」「拒绝访问」等 ≤4 字标签，状态码与原因留在悬停提示。链接检测与文档修复共用 `statusWord` / `statusTone`。
- **认图靠缩略图**：三个列表都加 36–40px 缩略图。文件名多是 `clipboard_image_…`，没有缩略图根本认不出是哪张；坏链接用同一张图在其他图床的可用副本当预览。
- **链接检测默认看「有问题」**：失效 + 超时 + 可疑合在一起；只有一类问题时不再重复显示子筛选；检测过且没有问题时显示绿色的「没有发现问题」，不再是「当前筛选暂无结果」。
- **文档修复不弹策略框**：替换来源在扫描结束时就按「已存首选 → 否则最快」定好并显示在列表上，可逐行换、可「以后优先用 X，应用到全部」。修改前自动备份、事后可撤销，确认框只是多余的一步。
- **「删除」改叫「移除记录」**：它只改 PicNexus 自己的记录，确认框写明「图床上的文件不会被删除」。
- **已删除的存储配置**显示为「WebDAV（已删除）」而不是随机 ID；没查配置（接线漏了）时仍显示 ID，便于排查。
- **运行中的进度**写进状态标签（「检测中 12 / 17」「迁移中 3 / 18」），不恢复圆环和百分比，底栏保持安静。
- **多选可见**：一旦有选中项，每行缩略图角上露出勾选圈；行可以 Tab 聚焦、空格 / 回车选中。

不做「按图片合并成一行、多个图床做子标签」：选择、批量删除、分页都是按「一份链接」设计的，合并后语义要整体重写；行上的「其他图床正常 / 无备份」提示已经回答了「图还在不在」。

不做标签页上的问题数角标：进入链接检测默认就停在「有问题」，角标只是重复信息。

## 验收记录

- 真机：Tauri 开发版 + WebView2 调试端口，用真实历史库（12 张图 / 17 条链接）走查三页亮暗两色；文档修复用临时目录里的测试文档实跑（逐行改来源后写入文件内容已核对，部分失败、全部正常两种结局都看过）；批量迁移不在真实账号上执行，进行中 / 完成态用视觉测试夹具核对。
- 自动化：单元测试全部通过；新增 / 改动的断言都先改坏被测代码确认会红；`npm run ci:prepush` 通过；e2e 冒烟（Chromium）8/8；三页视觉基准图已按新设计重录并复跑通过。
- 修掉的缺陷：检测完成后列表行停在「未检测」（单行组件只拿行引用，原地改写不刷新，已加回归测试）；部分失败时写入失败的行仍显示可点的「→ 图床」；需手动行多一个按钮把整列推歪。
