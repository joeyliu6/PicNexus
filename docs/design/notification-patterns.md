# 弹窗与通知

> 新增或修改「弹一下提醒」的代码前先读这份。规则来自交接说明第 4、6.2、9 节与 `T05-Toasts.dc.html`、`Patterns.dc.html`；各页「设计没画」的通知做法在 [decisions/](./redesign/decisions/)。

## 1. 通道

| 通道 | 写法 | 什么时候用 |
|---|---|---|
| 界面本身 | 卡片、按钮原地变化（「✓ 已复制」、结果条、红字原因） | 结果就在用户眼前：首页在屏时的上传结果、测试连接结果、设置「已保存」、更新卡片的失败 |
| 通知 | `useToast().success / error / warn / info(标题, 说明?)` | 结果不在眼前，或批量操作需要数字回执 |
| 带动作的通知 | `useToast().withAction(...)` | 通知里给一个下一步（「去登录」「重试」） |
| 撤销通知 | 先生效的：`useToast().withAction(…, { label: '撤销', run }, { countdown: true })`；要等调用方决定是否回滚或到时间才执行的：`useUndoToast().show(标题, 秒数?, kind?)` | 能撤销的操作，通知带「撤销」与倒计时细线（改用备份、修复、图库移除记录、删除压缩方案、清空全部记录） |
| 确认框 | `useConfirm()`，`tone: 'danger'` 画红 | 只给不可逆的危险操作（覆盖本地、清空全部记录、恢复默认设置…） |
| 对话框 | `PnDialog` | 需要输入或选择（备份密码、文档修复、补充备份、从 URL 下载） |
| 页内横幅 | 页面顶部常驻 | 需要用户稍后处理、不能自动消失（设置页「刷新后生效」） |
| 系统通知 | `useToast` 自动改走 | 主窗口隐藏到托盘或最小化时（托盘、全局快捷键、自动上传剪贴板发起的上传靠它告知结果）；带动作的通知仍留在应用里 |
| 不提示 | `useToast().silent(...)` 只写日志 | 单条复制这类高频、结果显而易见的动作 |

**能撤销的不弹确认**（交接说明第 4 节）：「改用备份」「修复」不弹确认、通知带撤销；只有危险且撤不回的操作才确认。

## 2. 通知的样子与规则（`PnToaster` + `toastStore.ts`）

- 右下角，宽 360、圆角 14；最多叠 3 条，新的在最下面，旧的略淡。
- 四种：成功（绿 ✓）/ 失败（红 ✕）/ 警示（琥珀 !）/ 带「撤销」（绿 ✓ + 底部 2px 品牌蓝倒计时细线）。还没执行、到时间才执行的危险操作（「将清空所有历史记录」）用琥珀。
- 停留：普通 4 秒，撤销类 6 秒（调用方可另给，如清空记录 5 秒）；`life: 0` 不自动消失、只会被挤掉，只给必须去处理的启动提示用。鼠标停在通知区时全部暂停计时。
- 超过 3 条先挤掉最旧的普通通知，撤销类尽量留着；被挤掉或到时间的撤销通知按「生效」处理。每一轮撤销各管各的，新的一轮不会撤掉上一轮。
- 种类、标题、说明完全相同的普通通知 2 秒内只出一次。
- 通知在对话框之上（`--pn-z-toast` 1200 > `--pn-z-dialog` 1100）。
- 确认框一次只显示一个，排队；点遮罩或 Esc 关闭时「确认」「取消」两个结果都不算。

## 3. 决策树

```
结果用户已经看得见（卡片、按钮、列表变了）？ ── 是 → 不弹
        │否
能撤销？ ── 是 → 撤销通知，不确认
        │否
不可逆且危险？ ── 是 → 确认框（tone: 'danger'）
        │否
用户必须稍后处理、不能自动消失？ ── 是 → 页内横幅（启动时的个别提示用 life: 0）
        │否
有下一步可以直接点？ ── 是 → 带动作的通知
        │否 → 普通通知（失败 = 原因 + 处理办法）
按钮已经禁用 / 隐藏、走不到的分支 → 不弹，直接 return
```

## 4. 文案

- 固定状态词：正常 / 失效 / 可能受限 / 等待中 / 上传中 / 已完成。成功写「已 + 动词」（已上传、已同步、已改用备份：3 张），失败写「XX 失败」或「未能 XX」。
- 错误 = 原因 + 处理办法：「无法连接 GitHub，请稍后重试」。处理办法指向此刻点得到的地方：凭证、登录、测试连接在**图床页**；格式、快捷键、同步、编辑器在**设置**；失败的图片在**首页**重试。
- 颜色只表达两种问题：红 = 刚才的操作失败了；琥珀 = 需要留意的状态。正常状态不打任何标记。
- 数字与单位间留空格（「21 张」「18 MB」），大数字千分位。
- 确认框的危险按钮写动作（「清空」「覆盖本地」），不写「确定」；正文写「会发生什么 + 能不能撤销」。
- 撤销后只说「已撤销」，不加说明（撤销的可能是任何操作）。

```ts
// 不可逆的危险操作
await confirm('将删除本机全部上传记录与收藏，图床上的文件不受影响。确认后有 5 秒可以撤销。', {
  header: '清空全部记录？', acceptLabel: '清空', rejectLabel: '取消', tone: 'danger',
});

// 先生效、可撤销
const kept = await undo.show(`已删除方案「${preset.name}」`);
if (!kept) restorePreset();
```

## 5. 不要这样做

| 反例 | 为什么 |
|---|---|
| 清空列表后再弹「已清空」 | 列表空了就是反馈 |
| 按钮已经 `v-if` 隐藏，还写「无需重试」通知 | 永远走不到 |
| 「开始检测」通知 | 进度已经在动 |
| 单条复制弹「已复制」 | 按钮原地变「✓ 已复制」就够了 |
| 更新卡片失败再弹一条同样的失败通知 | 卡片上已有原因与「重试」 |
| 用会消失的通知承载「请刷新页面」 | 用户必然错过，用页内横幅 |
| 处理办法写「请到设置里配置图床」 | 设置页没有图床，指到图床页 |
