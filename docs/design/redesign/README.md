## 怎么区分「已定」和「待过目」

- 「已定的事」「按交接说明去掉的旧功能」：与维护者一起定的，照做。
- 「设计没画、开发时补的（…）」各节、`health-plan.md` 里「开发时自定的」：AI 按交接说明的规则自行补的做法，**全部阶段做完后统一请维护者过目**，不同意的再改。
- 标 **待拍板** 的：设计稿自相矛盾、必须维护者选一个的，同样留到最后一起定。

## 已定的事

- 零件：Reka UI + 自写 `Pn*` 组件 + scoped CSS，不用 Tailwind / shadcn-vue（理由见 tech-stack 第 2 节）。
- 分支 `feat/redesign`，每阶段门禁全绿就提交，不 push。
- 图床配置沿用两层字段，不迁移：`availableServices` = 已添加，`enabledServices` = 启用 = 首页「上传到」勾选的那些。「已添加」= 在 `availableServices` 里，并且免配置或已填凭证。
- 「复制」可固定某个图床；固定的图床失败时退回「最先完成」（设计未画，按最接近的规则补）。上传与复制的完整规则见 [upload-flow.md](../../flows/upload-flow.md) 图 1 与「重试」不变量 4。
- 新配置字段只加不改、有默认值：复制固定图床（`linkOutput.copyFromService`）、文档文件夹、自动检测（默认每 7 天）。渐进提示「只出现一次」记在本机 localStorage（`picnexus-hint-fast-upload`），不进配置。
- 通知：最多叠 3 条时先挤掉最旧的普通通知，带「撤销」倒计时的尽量留着（免得来不及撤销就生效）；确认框排队，一次只显示一个。
- 侧栏：窗口窄于 1000px 强制收成图标栏且不给「展开」（展开后内容区只剩 592px，会横向滚动）；宽窗口下 `Ctrl+\` 手动收起，记在本机 localStorage，不进配置、不随云同步。
- 尚未重写的旧页面挂在新外壳里，由外壳代画顶部标题行与窗口按钮（路由 `meta.legacyTitle`）；`/hosts` 过渡期复用 SettingsView 的图床面板（`fixedTab`）。
- 拖入与 `Ctrl+V` / `⌘V` 是全局上传入口，任何页面都接（输入框内、弹窗打开时不接）；过渡期链接健康页不接拖入，留给旧的文档修复接 .md，阶段 5 改回。
- 传输中心现在只有「上传」一组；「备份」「检测」两组随阶段 5 加。
- 视觉基准：新界面在 `tests/redesign/`，跑真应用 + `tests/e2e/mocks` 的原生接口模拟（配置、历史、上传结果都在页面加载前写进去），每页一份 `*.visual.spec.ts`，图名前缀是画板编号；1400×900 与 800×600、浅深各一套。`npm run test:visual:update` 重录。

## 设计没画、开发时补的（首页）

- 上传进行中再拖入或粘贴：提示「请稍候」，不排队（沿用现有行为）。
- 上传失败的说法（交接说明第 9 节「错误 = 原因 + 处理办法」）：认得出的原因用固定说法——网络超时、网络连接中断、登录已过期（Cookie 登录的图床）/ 凭证无效（其余）、文件超出图床大小限制、图床不支持此格式、图床服务异常；认不出的保留原文。整张失败时接处理办法，超时照设计稿写「网络超时。请检查网络后重试。」。代码在 `src/utils/uploadFailureMessage.ts` 的 `describeUploadFailure`。
- 首页在屏时，单张失败与整批结果都不弹通知（卡片上已经画出来）；在别的页面拖入或粘贴时照常弹。
- 焦点卡在第一个图床传完前显示占位图，不做本地预览。
- 焦点卡失败时可「换个图床」只给这一张重传（复用「上传到」浮层的单次模式）。
- 从 URL 下载：不逐行标出无效链接，沿用现有通知（链接无效 / 超过数量上限）。
- 花瓣角标数字用 9px，是字号刻度外的例外（设计稿原值，令牌 `--pn-size-petal-badge-text`）。
- 「最近上传」的「清空」只清这个列表（焦点卡留着），不删图库记录，也不跨重启记住；上传中不可清空。
- 某个图床没传上（批量）：每个图床一行，写清几张没传上；进行中只在登录已过期时说「本批不会上传到 X」，其余失败等整批结束再报，并给「补传」（整批补传这个图床）。
- 批量缩略图点了复制：那一块盖一层绿色对勾，1.5 秒后复原（照失败那层的做法）。
- 上传前发现网络不通：这几张照样出现在首页并标成失败（「网络连接中断，请检查网络后重试」），点「重试」时没网同样按一次失败收口；不在首页时弹通知。
- 没有可用图床时拖入：标题照设计「先启用一个图床」，下一句指向此刻点得到的地方（首页指「上传到」或「启用京东图床」，别的页面先回首页）；对话框或命令面板开着时不接拖入。
- 关掉全局快捷键时，「第一次使用」的「在任意程序中按…」和渐进提示里那句都不显示。
- 从 URL 下载的提交键：Windows / Linux 写「Ctrl Enter」，macOS 写「⌘ Enter」（设计稿只画了前者）。
- 命令面板底栏跟着选中项说 Enter 做什么：图片是「复制链接」并加「Ctrl+Enter 在图库中定位」，其余是「打开」。设计稿空输入时选中图片仍写「打开」，与交接说明「图片 Enter 复制链接」矛盾，以交接说明为准。
- 命令面板的「开始链接检测」现在只跳到链接健康页，阶段 5 改成直接开始检测。
- 点「重试」立刻重传：不再等 1–8 秒退避，也不再「重试 3 次后用尽」；不弹「正在重试」通知（卡片上看得到进度）。整张重试又失败时，每个图床各写各的原因。
- 「重试失败的」只重传整张失败的图；单张重试后，第一个图床传完就复制。
- 单个图床补传成功的通知写「已补传到 X」；「修复」一词只留给链接健康。
- 交接说明「同时传 3 张」：同时处理 3 张图，每个图床也同时收 3 张（原来每个图床限 2 张，3 张都传同一个图床时第 3 张要排队）。
- 普通通知（含错误通知）一律 4 秒消失，带「撤销」的 6 秒（设计稿只写了「普通通知 4 秒」）。
- 文件大小全应用统一写法：KB 取整，MB / GB 小于 10 时保留一位小数（「386 KB」「1.2 MB」「18 MB」），照设计稿示例。
- 批量正在传时改「复制为」的格式：等这批结束，按新格式一次复制。
- 「上传到」旁的 ⚠ 图标悬停说明哪个图床传不上、为什么（如「微博登录已过期，暂时传不上」）；设计没画这个说明。
- 失败卡的「换个图床」浮层里，「上传这一张」用次要按钮：失败卡的「重试」已经是这一页唯一的主按钮。
- 弹出层、菜单、子菜单离窗口边缘至少 8px（Reka 默认放不下时贴着窗口边）。

## 设计没画、开发时补的（图库）

- 历史、时间轴、收藏三个旧页合成图库一页：收藏是筛选条件之一（「★ 收藏」），列表与网格用同一份筛选。
- 按「失效」筛选时仍按天分组（**待拍板**：设计稿 G06 / G07 背后的网格分成「失效 · 有可用备份 / 无可用备份」两组，交接说明 8.2 正文写的是按天分组）。
- 详情面板没有关闭按钮（设计稿没画）：`Esc` 收起，再点一次正开着的那张也收起。
- 双击开灯箱，第一下打开的详情留着；第一下打开详情后网格变窄重排，500 ms 内的第二下落到别的格子上时，开的仍是第一下点的那张。
- 打开详情、网格变窄重排时：停在最顶上就留在最顶上（G05），否则视口中间那张留在原位置。
- 行高照 GalleryScreen 用 150，窄窗口也是 150（K02 / K03 画的就是 150）。**待拍板**：ImageRatios（G13）的说明写「窄窗口 120」。
- 页面一直开着跨过午夜：「今天 / 昨天」在午夜和每次切回图库时按当天重算。
- 换筛选时计数与空状态沿用上一次的结果，等新统计回来再换，不闪「共 0 张」「暂无图片」。
- 列表的排序在网格 / 列表之间切换时保留；换排序或筛选后屏幕上的行立刻重取。
- `Ctrl/⌘ A` 全选当前筛选下的全部结果，不只是已经加载出来的那几天。
- 花瓣只数份数，一份一片、全是品牌蓝（同 GalleryScreen）；哪份有问题由 ⚠ 角标、详情与灯箱顶栏说。
- 重新检测：查出失效时通知用琥珀色（需要留意的状态），全部正常才是绿色的成功。
- 详情的图床行：尚未检测、可能受限的那份也能复制，只有「图片已不存在」的不给复制；⋯ 菜单是「改用这一份 / 重新检测 / 在浏览器打开 / 移除这条链接…」（移除前确认）。
- 列表行的 ⋯ 菜单：查看详情 / 查看大图 / 在浏览器打开 / 移除记录；窗口窄于 900px 时列表去掉「尺寸 · 大小」一列。
- 「移除记录」不弹确认，通知「已移除 N 条记录 · 图床上的图片不受影响」带「撤销」（原样插回，含收藏与检测结果）。
- 多选栏「复制链接 ▾」按 CopyMulti ③：先选格式，再选「复制时使用的链接」或指定从哪个图床复制；失效的链接不复制（CopyMulti：失效的置灰、不能点），没有可用链接的跳过并在通知里写张数。
- 灯箱：「换个图床」只换这次看的那份，不改「复制时使用」；`I` 或「信息」打开详情；滚轮缩放，不换图。菜单开着时 `Esc` 只关菜单、方向键在菜单里走。从列表打开时 ← → 按列表眼前的顺序翻，「3 / 21」是列表里的第几行。
- 不同比例（G13）：长图格子只写「长图」（1:2.5 的格子只有 48–60 px 宽，放不下画板上的「长图 1:5.6」，说明文字本来就写「标『长图』」）；短边小于 120 的小图优先于长图 / 全景的规则（裁切格会把图标、徽章放大得更糊）；同一角放不下两个角标时健康角标优先（「长图」与原尺寸让位，全景的比例留着）。
- 透明：数据库没记每张图是否真透明，按格式判断，JPEG 以外都在图片底下衬棋盘格（不透明的图会把它整个盖住）。动图只认 GIF：动态 WebP 从扩展名看不出来，按静态图显示。
- 预览框（详情、首页焦点卡）按 G13 的规则用这张图的模糊放大版填空白（G05 与首页画板画的是灰底，以 G13 的专门规则为准）；原图比框小时不放大。
- 灯箱里的长图（高宽比超过 2.5）：按窗口宽度、不超过原尺寸从顶部显示，滚轮上下滚动，`Ctrl`+滚轮缩放，点一下看全貌。
- 在「★ 收藏」筛选下取消收藏：那张留在原处（星标变空），重新进筛选才消失，免得点完图跳走。
- 命令面板 `Ctrl+Enter` / `⌘Enter`「在图库中定位」：回到网格、清掉会把它筛掉的条件，跳到它那一天，选中并打开详情。
- 刻度条拖动经过很多个月时只跳最后停下的那个月（跳转中的请求只留最后一个）。点年份跳到这一年最新的那个月（年份写在它各月之上，代表这一年最近的部分）。
- 键盘与读屏：网格只有一个 Tab 停留点（详情 / 焦点那张，没有就是视口里第一张），方向键走、焦点跟着走；Enter 详情、空格灯箱。读屏看到「日期行 → 图片行 → 格子」，格子读文件名，再读 ⚠ 状态、已收藏、长图 / 全景 / 原尺寸、GIF。刻度条排在图片之后，Tab 到时浮出并显示当前月的气泡，↑ ↓ 换一格、PageUp / PageDown 一次 5 格、Home / End 到最新 / 最旧。列表同样只有一个 Tab 停留点，↑ ↓ / Home / End / PageUp / PageDown 换行，Enter 详情、空格灯箱；这一行的「复制」「⋯」接在它后面。
- 键盘不能单独选中某一张（设计没给按键，空格已是灯箱）：多选靠鼠标（Ctrl / Shift 单击）或 `Ctrl/⌘ A` 全选。
- 格子窄到放不下角标时（窄窗口打开详情，长图格子可能只剩 20 多 px）：长图 / 全景 / 原尺寸不画，⚠ 角标只留 ⚠，「仅 1 份」不画；窄到连 ⚠ 都放不下（约 33px 以下）就什么角标都不画。读屏与详情照常说明。
- 灯箱的顶栏、底栏是实心深色底：长图、放大的图平移时从它们下面经过，不盖住按钮；窄窗口里底栏按钮不折行，文件信息与图床名放不下时以「…」截断。
- 空状态的尺寸（说明文字 13px、各段间距）以图库 G09–G11 为准，所有页面的空状态共用这一份；Patterns 画板里的空状态略有出入。
- 预览框的模糊衬底不跟「减少视觉效果」开关走：只有详情与首页焦点卡两处、面积小。
- Markdown 格式的 alt 保留扩展名（`![截图.png](…)`），设计稿示例里没有扩展名（**待拍板**：首页与图库共用同一个格式器，改了两处一起变）。

## 平台限制记录

- **侧栏材质**：不用 Mica / 毛玻璃，三平台都用令牌里的纯色侧栏（浅色 Windows `#F3F3F3` / macOS `#ECECEC` / Linux `#F4F4F4`，深色 `#151517`）。理由：Mica 只在 Windows 11 生效，需要整窗透明，Windows 10 上会露底；开发机是 Windows 10，macOS 无真机，都没法验证。
- **macOS 红绿灯**：`tauri.macos.conf.json` 设 `titleBarStyle: Overlay`、`trafficLightPosition {18, 20}`，没有在 macOS 真机上看过位置；收起成图标栏时 Logo 行留空给红绿灯。
- **Windows 关闭键悬停**：沿用系统外观（红底白叉 `#C42B1C`），设计稿没画悬停态。
- （待实测：原生托盘菜单能否勾选后不关、Windows 默认项加粗、WebKit 毛玻璃。）
