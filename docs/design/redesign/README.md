## 怎么区分「已定」和「待过目」

- 「已定的事」「按交接说明去掉的旧功能」：与维护者一起定的，照做。
- 「设计没画、开发时补的（…）」各节：AI 按交接说明的规则自行补的做法，**全部阶段做完后统一请维护者过目**，不同意的再改。
- 标 **待拍板** 的：设计稿自相矛盾、必须维护者选一个的，同样留到最后一起定。

## 已定的事

- 零件：Reka UI + 自写 `Pn*` 组件 + scoped CSS，不用 Tailwind / shadcn-vue（理由见 tech-stack 第 2 节）。
- 分支 `feat/redesign`，每阶段门禁全绿就提交，不 push。
- 图床配置沿用两层字段，不迁移：`availableServices` = 已添加，`enabledServices` = 启用 = 首页「上传到」勾选的那些。「已添加」= 在 `availableServices` 里，并且免配置或已填凭证。
- 「复制」可固定某个图床；固定的图床失败时退回「最先完成」（设计未画，按最接近的规则补）。上传与复制的完整规则见 [upload-flow.md](../../flows/upload-flow.md) 图 1 与「重试」不变量 4。
- 新配置字段只加不改、有默认值：复制固定图床（`linkOutput.copyFromService`）、文档文件夹、自动检测（默认每 7 天）。渐进提示「只出现一次」记在本机 localStorage（`picnexus-hint-fast-upload`），不进配置。
- 通知：最多叠 3 条时先挤掉最旧的普通通知，带「撤销」倒计时的尽量留着（免得来不及撤销就生效）；确认框排队，一次只显示一个。
- 侧栏：窗口窄于 1000px 强制收成图标栏且不给「展开」（展开后内容区只剩 592px，会横向滚动）；宽窗口下 `Ctrl+\` 手动收起，记在本机 localStorage，不进配置、不随云同步。
- 尚未重写的旧页面挂在新外壳里，由外壳代画顶部标题行与窗口按钮（路由 `meta.legacyTitle`）。图床的连接、凭证、启用只在图床页（`src/views/hosts/`）；设置页不再有图床分组，表单从不写图床配置。
- 拖入与 `Ctrl+V` / `⌘V` 是全局上传入口，任何页面都接（输入框内、弹窗打开时不接）。
- 传输中心按任务分组：上传、补充备份、链接检测，没有的组不出现。
- 视觉基准：新界面在 `tests/redesign/`，跑真应用 + `tests/e2e/mocks` 的原生接口模拟（配置、历史、上传结果都在页面加载前写进去），每页一份 `*.visual.spec.ts`，图名前缀是画板编号；1400×900 与 800×600、浅深各一套。`npm run test:visual:update` 重录。

## 设计没画、开发时补的（首页）

- 上传进行中再拖入或粘贴：提示「请稍候」，不排队（沿用现有行为）。
- 上传失败的说法（交接说明第 9 节「错误 = 原因 + 处理办法」）：认得出的原因用固定说法——网络超时、网络连接中断、登录已过期（Cookie 登录的图床）/ 凭证无效（其余）、文件超出图床大小限制、图床不支持此格式、图床服务异常；认不出的保留原文。整张失败时接处理办法，超时照设计稿写「网络超时。请检查网络后重试。」。代码在 `src/utils/uploadFailureMessage.ts` 的 `describeUploadFailure`。
- 首页在屏时，单张失败与整批结果都不弹通知（卡片上已经画出来）；在别的页面拖入或粘贴时照常弹。
- 焦点卡在第一个图床传完前显示占位图，不做本地预览。
- 焦点卡失败时可「换个图床」只给这一张重传（复用「上传到」浮层的单次模式）。
- 从 URL 下载：不逐行标出无效链接，沿用现有通知（链接无效 / 超过数量上限）。
- 花瓣角标数字用 9px，是字号刻度外的例外（设计稿原值，令牌 `--pn-size-petal-badge-text`）。
- 「最近上传」的「清空」只清这个列表（焦点卡留着），不删图库记录，也不跨重启记住；上传中不可清空。
- 某个图床没传上（批量）：每个图床一行，写清几张没传上；进行中只在登录已过期时说「本批不会上传到 X」，其余失败等整批结束再报，并给「补传」（整批补传这个图床）。
- 批量缩略图点了复制：那一块盖一层绿色对勾，1.5 秒后复原（照失败那层的做法）。
- 上传前发现网络不通：这几张照样出现在首页并标成失败（「网络连接中断，请检查网络后重试」），点「重试」时没网同样按一次失败收口；不在首页时弹通知。
- 没有可用图床时拖入：标题照设计「先启用一个图床」，下一句指向此刻点得到的地方（首页指「上传到」或「启用京东图床」，别的页面先回首页）；对话框或命令面板开着时不接拖入。
- 关掉全局快捷键时，「第一次使用」的「在任意程序中按…」和渐进提示里那句都不显示。
- 从 URL 下载的提交键：Windows / Linux 写「Ctrl Enter」，macOS 写「⌘ Enter」（设计稿只画了前者）。
- 命令面板底栏跟着选中项说 Enter 做什么：图片是「复制链接」并加「Ctrl+Enter 在图库中定位」，其余是「打开」。设计稿空输入时选中图片仍写「打开」，与交接说明「图片 Enter 复制链接」矛盾，以交接说明为准。
- 命令面板的「开始链接检测」：跳到链接健康页并直接开始全量检测（正在检测时只跳过去）。
- 点「重试」立刻重传：不再等 1–8 秒退避，也不再「重试 3 次后用尽」；不弹「正在重试」通知（卡片上看得到进度）。整张重试又失败时，每个图床各写各的原因。
- 「重试失败的」只重传整张失败的图；单张重试后，第一个图床传完就复制。
- 单个图床补传成功的通知写「已补传到 X」；「修复」一词只留给链接健康。
- 交接说明「同时传 3 张」：同时处理 3 张图，每个图床也同时收 3 张（原来每个图床限 2 张，3 张都传同一个图床时第 3 张要排队）。
- 普通通知（含错误通知）一律 4 秒消失，带「撤销」的 6 秒（设计稿只写了「普通通知 4 秒」）。
- 文件大小全应用统一写法：KB 取整，MB / GB 小于 10 时保留一位小数（「386 KB」「1.2 MB」「18 MB」），照设计稿示例。
- 批量正在传时改「复制为」的格式：等这批结束，按新格式一次复制。
- 「上传到」旁的 ⚠ 图标悬停说明哪个图床传不上、为什么（如「微博登录已过期，暂时传不上」）；设计没画这个说明。
- 失败卡的「换个图床」浮层里，「上传这一张」用次要按钮：失败卡的「重试」已经是这一页唯一的主按钮。
- 弹出层、菜单、子菜单离窗口边缘至少 8px（Reka 默认放不下时贴着窗口边）。

## 设计没画、开发时补的（图库）

- 历史、时间轴、收藏三个旧页合成图库一页：收藏是筛选条件之一（「★ 收藏」），列表与网格用同一份筛选。
- 按「失效」筛选时仍按天分组（**待拍板**：设计稿 G06 / G07 背后的网格分成「失效 · 有可用备份 / 无可用备份」两组，交接说明 8.2 正文写的是按天分组）。
- 详情面板没有关闭按钮（设计稿没画）：`Esc` 收起，再点一次正开着的那张也收起。
- 双击开灯箱，第一下打开的详情留着；第一下打开详情后网格变窄重排，500 ms 内的第二下落到别的格子上时，开的仍是第一下点的那张。
- 打开详情、网格变窄重排时：停在最顶上就留在最顶上（G05），否则视口中间那张留在原位置。
- 行高照 GalleryScreen 用 150，窄窗口也是 150（K02 / K03 画的就是 150）。**待拍板**：ImageRatios（G13）的说明写「窄窗口 120」。
- 页面一直开着跨过午夜：「今天 / 昨天」在午夜和每次切回图库时按当天重算。
- 换筛选时计数与空状态沿用上一次的结果，等新统计回来再换，不闪「共 0 张」「暂无图片」。
- 列表的排序在网格 / 列表之间切换时保留；换排序或筛选后屏幕上的行立刻重取。
- `Ctrl/⌘ A` 全选当前筛选下的全部结果，不只是已经加载出来的那几天。
- 花瓣只数份数，一份一片、全是品牌蓝（同 GalleryScreen）；哪份有问题由 ⚠ 角标、详情与灯箱顶栏说。
- 重新检测：查出失效时通知用琥珀色（需要留意的状态），全部正常才是绿色的成功。
- 详情的图床行：尚未检测、可能受限的那份也能复制，只有「图片已不存在」的不给复制；⋯ 菜单是「改用这一份 / 重新检测 / 在浏览器打开 / 移除这条链接…」（移除前确认）。
- 列表行的 ⋯ 菜单：查看详情 / 查看大图 / 在浏览器打开 / 移除记录；窗口窄于 900px 时列表去掉「尺寸 · 大小」一列。
- 「移除记录」不弹确认，通知「已移除 N 条记录 · 图床上的图片不受影响」带「撤销」（原样插回，含收藏与检测结果）。
- 多选栏「复制链接 ▾」按 CopyMulti ③：先选格式，再选「复制时使用的链接」或指定从哪个图床复制；失效的链接不复制（CopyMulti：失效的置灰、不能点），没有可用链接的跳过并在通知里写张数。
- 灯箱：「换个图床」只换这次看的那份，不改「复制时使用」；`I` 或「信息」打开详情；滚轮缩放，不换图。菜单开着时 `Esc` 只关菜单、方向键在菜单里走。从列表打开时 ← → 按列表眼前的顺序翻，「3 / 21」是列表里的第几行。
- 不同比例（G13）：长图格子只写「长图」（1:2.5 的格子只有 48–60 px 宽，放不下画板上的「长图 1:5.6」，说明文字本来就写「标『长图』」）；短边小于 120 的小图优先于长图 / 全景的规则（裁切格会把图标、徽章放大得更糊）；同一角放不下两个角标时健康角标优先（「长图」与原尺寸让位，全景的比例留着）。
- 透明：数据库没记每张图是否真透明，按格式判断，JPEG 以外都在图片底下衬棋盘格（不透明的图会把它整个盖住）。动图只认 GIF：动态 WebP 从扩展名看不出来，按静态图显示。
- 预览框（详情、首页焦点卡）按 G13 的规则用这张图的模糊放大版填空白（G05 与首页画板画的是灰底，以 G13 的专门规则为准）；原图比框小时不放大。
- 灯箱里的长图（高宽比超过 2.5）：按窗口宽度、不超过原尺寸从顶部显示，滚轮上下滚动，`Ctrl`+滚轮缩放，点一下看全貌。
- 在「★ 收藏」筛选下取消收藏：那张留在原处（星标变空），重新进筛选才消失，免得点完图跳走。
- 命令面板 `Ctrl+Enter` / `⌘Enter`「在图库中定位」：回到网格、清掉会把它筛掉的条件，跳到它那一天，选中并打开详情。
- 刻度条拖动经过很多个月时只跳最后停下的那个月（跳转中的请求只留最后一个）。点年份跳到这一年最新的那个月（年份写在它各月之上，代表这一年最近的部分）。
- 键盘与读屏：网格只有一个 Tab 停留点（详情 / 焦点那张，没有就是视口里第一张），方向键走、焦点跟着走；Enter 详情、空格灯箱。读屏看到「日期行 → 图片行 → 格子」，格子读文件名，再读 ⚠ 状态、已收藏、长图 / 全景 / 原尺寸、GIF。刻度条排在图片之后，Tab 到时浮出并显示当前月的气泡，↑ ↓ 换一格、PageUp / PageDown 一次 5 格、Home / End 到最新 / 最旧。列表同样只有一个 Tab 停留点，↑ ↓ / Home / End / PageUp / PageDown 换行，Enter 详情、空格灯箱；这一行的「复制」「⋯」接在它后面。
- 键盘不能单独选中某一张（设计没给按键，空格已是灯箱）：多选靠鼠标（Ctrl / Shift 单击）或 `Ctrl/⌘ A` 全选。
- 格子窄到放不下角标时（窄窗口打开详情，长图格子可能只剩 20 多 px）：长图 / 全景 / 原尺寸不画，⚠ 角标只留 ⚠，「仅 1 份」不画；窄到连 ⚠ 都放不下（约 33px 以下）就什么角标都不画。读屏与详情照常说明。
- 灯箱的顶栏、底栏是实心深色底：长图、放大的图平移时从它们下面经过，不盖住按钮；窄窗口里底栏按钮不折行，文件信息与图床名放不下时以「…」截断。
- 空状态的尺寸（说明文字 13px、各段间距）以图库 G09–G11 为准，所有页面的空状态共用这一份；Patterns 画板里的空状态略有出入。
- 预览框的模糊衬底不跟「减少视觉效果」开关走：只有详情与首页焦点卡两处、面积小。
- Markdown 格式的 alt 保留扩展名（`![截图.png](…)`），设计稿示例里没有扩展名（**待拍板**：首页与图库共用同一个格式器，改了两处一起变）。

## 设计没画、开发时补的（链接健康）

流程与数据口径见 [link-check-flow.md](../../flows/link-check-flow.md)（健康模型、页面状态）、[md-rescue-flow.md](../../flows/md-rescue-flow.md)（修复与撤销）、[batch-migrate-flow.md](../../flows/batch-migrate-flow.md)（补充备份）。

**口径**
- 「仅有 1 份」= 没被查出失效的副本只剩 1 份（尚未检测的当作可用）。与图库「状态 · 仅 1 份」筛选（按上传成功的份数）口径不同。
- 失效原因只分三种：图片已不存在 = 404 / 410；连接超时 = 超时、连不上、图床 5xx；拒绝访问 = 其余（401 / 403 / 429、被本机安全策略拦下、返回的不是图片等）。「拒绝访问」「连接超时」给「重试」，「图片已不存在」且无备份不给按钮。
- 旧版本留下的「检测排队中（pending）」结果当作尚未检测（与图库「失效」筛选、侧栏琥珀点同一口径）。
- 「上次检测」与自动检测的计时 = 全部检测结果里最旧的那条（每轮全量检测会把每一份都查一遍）：单行「重试」「仅重新检测失效图片」不让它们归零。一周以上写日期（「10月9日」）。
- 检测进行中，只有复制时使用的那份等这一轮的新结果，备份照旧用上一次的结果（L02 画的就是「可改用备份」一组）。
- 全量检测预计时间按每条链接 0.035 秒估，写「约需 N 分钟」，不足 1 分钟写「不到 1 分钟」。

**状态栏**
- 「集中在…」：失效图片的上传年份写成「Y 年」或「Y1–Y2 年」（跨度超过 6 年不写年份）；某个图床占失效的八成以上才写「上传到 X」；两样都不成立就不写这一句。
- 一张都修不了时只给「重新检测」，说明写「均无可用备份 · 本次会话 N 张已修复」（L11）。全部正常但有可能受限的：「N 张图片均可访问 · 另有 N 张可能受限 · 上次检测：…」。
- 读取中只留位置不写字；读取失败写「未能读取检测记录 · 请稍后重试」+「重试」。
- 「⋯」里数量为 0 的项不出现，从没检测过不给「导出结果（CSV）」；检测 / 修复中没有「⋯」。自动检测关闭时子菜单右边写「已关闭」。导出文件名 `link-check-<时间戳>.csv`，成功通知「已导出检测结果」。
- 「清理找不回的图片…」确认后移除这些记录，通知带「撤销」（原样放回）。

**上传日历**
- 年份胶囊：有上传的年份加上今年，从新到旧最多 6 个，其余进「更早 ▾」菜单（每项带失效张数）；选中的年份在「更早」里时，胶囊直接写这一年。默认年份只在第一次读完数据时按规则选，之后保留用户的选择。
- 键盘：整张日历一个 Tab 停留点（选中的那天 > 上次聚焦的那天 > 今天），方向键按天 / 周、Home / End 到年首 / 年尾，Enter 或空格筛到这一天，再按一次取消。读屏用 `role="group"` + 一句描述、每格是按钮并读「日期 · 上传 N 张 · N 张失效」（交接说明 11 写的 `role="img"` 会让单格读不到）。
- 气泡：悬停与键盘聚焦时出现，鼠标点过之后移开不留着。未来的日子不能点。
- 星期标签 10px 是字号刻度外的例外（设计稿原值，令牌 `--pn-size-calendar-weekday-text`，同花瓣角标 9px）。
- 366 天且 1 月 1 日是周日的年份画 54 列。

**工具卡**
- 读取中三张卡只留标题，不写数字和结论（免得先闪一下好消息）。
- 文档修复卡：正在读取文件夹时写「正在读取文档文件夹」；有失效引用但都没有备份时写「N 处失效图片，均无可用备份」；修复更新过文档后写「N 个文档已更新 · 共替换 M 处旧链接，可撤销」+「查看…」，直到撤销通知消失；修复中没有文档要更新时照平常写。
- 补充备份卡：暂停时「已暂停 · 复制到 X」+「继续」；结束有失败时「已完成 · N 张未能备份」+「重试」（只重传失败的）；刚备份完、已没有「仅 1 份」的图才写「已完成 · 每张图片至少保存在 2 个图床」，还剩的照平常写张数；没有「仅 1 份」的图时写「每张图片至少保存在 2 个图床」、不给按钮。剩余时间按已用速度估。可用图床少于 2 个时写「需要另一个图床，当前只有 1 个可用图床」，一个都没有时写「需要至少 2 个图床，当前没有可用图床」（设计稿只画了前者）。
- 第三张：有「无可用备份」的图才是「找不回的图片 · N 张」（失效的全都能修时换回自动检测）。「查看」= 清单只留「无可用备份」一组，标题旁出现可移除的「无可用备份 ×」标签（与日期标签同一处，两个同时生效时只显示这一个）。
- 自动检测默认开、每 7 天；从没检测过不自动开始，卡片「开启」= 立即开始第一次检测；关掉后卡片同样写「开启」。「更改」与「⋯ › 自动检测」是同一个子菜单：每天 / 每 3 天 / 每 7 天 / 每 30 天 / 关闭。自动检测只在应用开着时跑（启动后 30 秒判一次，之后每小时），正在检测 / 修复 / 补充备份时跳过这一次。
- 工具卡与清单行的按钮左右内边距 12（设计稿；Pn 小号按钮默认 10）。

**全部失效图片**
- 行的备份说明：有可访问的备份写「X 有备份」；备份尚未检测「备份尚未检测」；备份受限「备份可能受限」；备份都失效「备份也已失效」；只有一份「无备份」。「用于 N 个文档」在没有文档文件夹或还没扫完时不写，有文件夹但没引用写「未被文档引用」。
- 按钮里的图床名超过 8 个字且带空格时只用最后一个词（「改用 R2」「已改用 R2」）；重试中按钮原地转圈写「检测中」；改用失败时行上红字「未能修复」。
- 三个筛选菜单每项带张数；「图床」只列有失效图片的图床，按张数从多到少。按「可能受限」筛选时只有一组「可能受限 N 张」，行上没有按钮，「⋯」里没有「移除失效链接…」。年份选「与上方日历同步」后按钮写「年份 与日历同步」。
- 筛选按钮藏起来时（窄窗口、检测中）原因 / 图床 / 年份三个筛选不生效。日期标签由日期本身算出，换了日历年份照样在、照样能移除。换筛选时「显示其余」已展开的行数清零；「显示其余 N 张」每次多 100 行，修复中不出现。
- 筛选后没有结果写「没有符合条件的失效图片」。行「⋯」菜单在下方放不下时向上展开。

**修复与撤销**
- 行内「改用 X」的通知：「已改用 X」+「已更新 N 个文档中的 M 处旧链接」（没有文档引用时写「复制的链接将来自 X」）；「修复 N 张」没有文档引用时写「复制的链接已改用备份」；只改了文档没切换图片时写「已更新 N 个文档 · 共替换 M 处旧链接」。都带「撤销」。
- 文档写不成：红色通知写第一条原因（多个时加「（另有 N 个）」）+「重试」；重试写成的另弹一条成功通知，并入原来那次修复，靠原通知撤销。改用失败：「N 张图片未能修复 · 记录已变化，请重新检测后重试」；撤销时切不回去：「N 张图片未能改回 · 请稍后在图库详情中手动改用」。
- 撤销时文档在修复后又被改过：不还原，「N 个文档未还原 · X 在修复后被修改过，已保留现在的内容」。
- 备份目录精确到毫秒（`YYYYMMDD_HHmmss_SSS`），同一秒里连着修两次不会盖掉第一次的原文；每个文档文件夹留最近 5 次。
- 同一时间只跑一个修复；命令面板「开始链接检测」在修复中只跳到页面。
- 「重新上传原图…」：选一张本地图片，传到这张图原来所在、现在仍可用的图床（都不可用时传到「上传到」勾选的图床），复制时使用的那份优先留在原来的图床，新链接替换失效的那几份，文档里的旧链接一并换掉；通知带撤销（记录与文档都还原，已传上去的新文件不删）；上传过程不单独显示进度。
- 「移除失效链接…」：只移除失效的那几份（确认框写明「移除后无法撤销」，文档里还引用着就写明）；每一份都失效时整条记录移除，与「清理找不回的图片」一样通知带「撤销」。

**文档文件夹**
- 添加的文件夹已在列表里（或在某个文件夹里面）不重复加，通知「已在文档文件夹中」；加的是已有文件夹的上一层，就收掉被它包含的那几个。
- 扫描出错：权限类写「没有读取权限」，其余一律写「文件夹不存在」，都用琥珀色写在这一行。弹窗里文件夹还在读时写「正在读取文档…」，读完没有失效写「文档中没有失效图片」、按钮只有「完成」；有失效但都没有备份时「修复 0 处」置灰；列表超过 5 行在框内滚动。没有文件夹时不显示「需要修复的文档」整块。
- 每次扫描前重新申请访问权限（授权只活在本次进程内）；进入页面、增删文件夹、修复后各扫一次，结果只放内存。
- 文档文件夹是本机路径：云同步合并配置时保留本机的这一份，自动检测设置照常同步。
- 文档里不是 PicNexus 上传的图片不检测、不计入、不替换；原始链接、加前缀的链接、剥掉已知前缀后的链接都认。

**补充备份**
- 弹窗列「已添加」的图床（含停用的），按配置顺序，「已有 N 张」只算没失效的；默认选能复制过去最多张的那个可选图床，一样多取靠前的。有警示的变淡不可选：Cookie 图床写「登录已过期，暂不可选」，其余写「暂不可用，请在图床页检查配置」。可用图床少于 2 个时卡片换成「添加图床」。
- 下载来源：只从没被查出失效的那几份下载（「复制时使用」的那份失效时从备份取）。
- 范围：「仅有 1 份」、且目标图床上还没有它的任何一份——已有一份失效的也不算（迁移管线会按「目标上已有」跳过，补不上）。预计时间按选中图床真正要复制的张数、每张 0.9 秒估（设计稿 1,206 张 ≈ 18 分钟）。

**外壳**
- 传输中心「补充备份到 X」组有「暂停 / 停止」，「链接检测」组有「暂停 / 取消」（照 H14），暂停时写「已暂停」、检测进度条变灰，没有「等待某图床」可写时写「正在检测」。结束后进「已完成」：「补充备份到 X · N 张」（全部失败才打 ✗）、「链接检测 · N 个链接」；中途取消的写「链接检测已取消 · 已查 N 个链接」（灰色 ✕）。标题栏传输图标的数字 = 还在传的图片张数 + 进行中的补充备份、链接检测各 1；进度环取各项任务进度的平均；任务都结束而传输中心还开着时画空环（同 HomeScreen 无任务时）。
- 侧栏「链接健康」的琥珀点：复制时使用的那份失效的图片数 > 0（与图库「失效」筛选同一条 SQL），启动时与每次检测、历史记录变化后刷新；宽侧栏与图标栏都画。
- 主栏宽度不足 990px（放不下整年 13px 的日历）时整页切到窄版式：日历 9px、工具卡去插画、清单去日期 / 文档两列与筛选、年份汇总隐藏（设计稿只画了 800×600）。

**待拍板**
- 第一次修复时没有文档文件夹：成功通知照常带「撤销」，另起一条「文档中的旧链接未更新」+「添加文档文件夹…」（只出现一次，记在本机 localStorage）。交接说明 15 节写「在成功通知里附」，与第 4 节「改用备份通知带撤销」放不进同一条通知（一条只有一个按钮）。
- 第 4 节第 7 条把「链接健康从未检测」列为可用背景装饰的空状态，L01 却没画装饰；现在照 L01 不加。
- 全部正常但有「可能受限」的图时，状态栏写了张数，但没有清单可看（L13 不显示清单）；要不要给个入口。
- 「等待微博响应」：HealthScreen 不带空格，H14 传输中心写「等待 微博 响应」；两处现在都按中英文交界补空格（「等待微博响应」「等待 Cloudflare R2 响应」）。

## 设计没画、开发时补的（图床）

**连接与断开**
- 连接 = 加进已添加**并启用**（刚接上就是要用它）；公共图床先过 P11。WebDAV / S3 新建的那份在「测试并连接」通过前只是页面里的草稿，关掉目录或换图床就丢弃；名字照「WebDAV 1」「S3 兼容存储 1」（现存最大序号 + 1），可点铅笔改（回车保存、Esc 取消，空名字或没改不保存）。
- 「测试并连接」时必填项没填：不发请求，那一格标红、红字「请填写 X」，结果条「X 未填写 · 请填写后再试」。
- 断开 = 从已添加、启用里去掉并清掉凭证，同时解除 Typora / Obsidian 对它的绑定，高级字段（自定义路径等）留着；不弹确认，通知「已断开 X / 已传的图片和链接不受影响」带倒计时「撤销」（按快照原样放回，含原来的位置）。它若是「复制」固定的图床，固定退回「最先完成」。WebDAV / S3 叫「删除这份…」，同样带撤销。断开最后一个也照常断开（一个都没有是正常状态：首页「没有图床」，图床页右侧直接是目录）。
- Cookie 图床的连接表单：没填 Cookie 时按钮「登录…」+「将在新窗口打开 X 官方登录页，登录后自动填入」；手动粘贴了 Cookie 后按钮改写「测试并连接」、不再开窗。会写入的图床写「将写入并删除一个测试文件」，京东 / 七鱼按钮叫「连接」。
- 进入图床页时，很早版本留下的单份「自定义 S3」（`services.custom_s3`）搬成一份多份配置（名字「自定义 S3」）：沿用旧设置页已有的迁移，只是挪到了图床页。

**字段与保存**
- 普通字段（已连接的图床）失焦且有改动即保存并自动测试一次；未连接的只改草稿。保存失败时红色通知「未能保存 / 原因，请重试」，界面不当作已保存。
- 敏感字段：点「查看」明文显示 30 秒；点「修改…」进入编辑，不输入就离开 = 取消，输入过又删空再离开 = 清空，先确认（「清空 X？ / 清空后需重新填写，否则无法上传到这个图床。」，红色「清空」）；查看失败通知「无法查看X / 请重新填写后再试」。Cookie 的密文前露出第一项的名字（「SUB=••••」，名字不是秘密），其余只有圆点。
- Cookie 字段旁「手动粘贴」= 把字段切成编辑态，粘贴后失焦保存并检测。过期日期拿不到时只写「登录信息将自动填入」。
- 「HTTP · 已允许」只标后端真会放行的明文地址：对象存储是确认过的公开域名；WebDAV 是写成 IP 的局域网 / 本机地址、P12 确认过的、或已连接且最近一次没测失败的。已连接的图床填 http 公开地址时先保存再弹 P12，点「取消」地址仍留在配置里（不测，下次测试再问）。
- P12 代码框列出要放行的地址：对象存储是公开域名；WebDAV 是明文 HTTP 且写成主机名的那几个（IP 地址不用确认），一次确认对这份配置的两个地址都生效。
- 测试指到的字段收在「高级选项」里时自动展开；改那一格时保持展开。对象存储的「高级选项」摘要写实际收起的字段（R2 只有「自定义路径」）；WebDAV 的高级选项是「链接模板、防止图片互相覆盖」，开关写明代价。
- R2「使用第三方服务加速缩略图」沿用现有默认（开），P04 画的是关。

**测试结果**
- 结果条只在本次页面会话里保留；左栏的 ⚠ 来自持久的健康状态（上传失败也会让它变琥珀）。京东 / 七鱼的检测结果不写进健康状态。测试中左栏第二行写「检测中…」。
- 成功：三步的写「服务可用 · Nms · 读取、写入、公开访问均通过」，一步的写「凭证有效 / 登录有效」，京东 / 七鱼只写「服务可用 · Nms」。GitHub 测读取、写入两步，公开访问不测（CDN 缓存延迟）。
- 失败：标题「<字段名>无效」（中文字段名不加空格，英文的照常「Secret Access Key 无效」；指不到字段时写原因本身），后面接已通过的几步 + 处理办法（按这个图床表单上的叫法）；字段下面红字写原因。改了标红那一格后红框清掉、标题不变，直到下一次测试。不写设计稿的「其余各项均通过」：前一步没过时后面根本没测。
- 原因怎么说：R2 的 TLS 握手被拒指到 Account ID；没有存储桶权限不指字段，写「密钥没有访问这个存储桶的权限，请在 X 后台为它授予读写权限」；连不上 / 超时不指字段，写「无法连接存储服务（WebDAV 服务器），请检查网络后重试」；WebDAV 公开链接失败写「请检查公开访问地址和链接模板」。原始错误只进日志。
- 左栏与头部的问题短标签：Cookie 图床一律「登录失效」，凭证类「凭证无效」，公开链接类「公开链接异常」，其余「连接异常」（设计只画了前两种）。公开链接返回 403 算公开链接异常，不算凭证。

**列表、目录、使用情况**
- 左栏：指针在清单里时先不重排，离开清单再按「有问题 → 已启用 → 停用」排（否则点「停用」后那一行立刻挪走，浮出的按钮落到另一个图床上）。右键菜单只有「启用 / 停用」。键盘：上下键、Home / End，整个清单只占一个 Tab 停留点。侧栏「图床」旁的琥珀点：已添加的图床有问题时出现。
- 「＋」在目录与连接表单里都保持按下的样子。一个图床都没有、或窄窗口时，目录不显示「关闭」。宽窗口下 Esc：连接表单回目录，目录回详情。目录搜索也搜「需要准备什么」那一行；没有结果写「没有符合条件的图床」。
- 「张最先完成」= 复制时使用的链接在这个图床上的张数；「张失效」= 复制时使用的那份在这个图床上且被查出失效的张数（与图库、链接健康同一口径），大于 0 时用琥珀色并可点，跳到链接健康按这个图床筛选。
- 设计没画的图床照最接近的画法：对象存储照 R2、Token 照 GitHub、Cookie 照微博、免配置照京东、自定义 S3 照 WebDAV；知乎沿用现有开关 + 参数值。
- 微博链接前缀沿用出厂列表（搜狗图片等，第一项标「（默认）」），最前面加「不加前缀」；右下角写实际支持的变量「{url} {path} {url_encoded}」。GitHub「存储路径」帮助写「图片在仓库中的目录」、「分支」写「默认 main」；加速列表沿用现有数据，「原始地址」放最后；「添加 CDN」填整条地址模板。「添加模板 / 添加 CDN」用弹窗；自己加的悬停可删、立即生效不撤销，出厂的不可删。

**Cookie 小窗与编辑器**
- 准备页 520×600（P16），点「开始登录」后放大到该网站登录页需要的尺寸；标题栏 40 高、侧栏底色，标题「微博登录」；macOS 用系统红绿灯、不画关闭键。「开始登录」失败时原因写在按钮下方（不弹系统对话框）。登录成功通知「已登录 微博」；60 秒超时通知「微博登录超时」，处理办法指向图床页的「重新登录」与「手动粘贴」。

## 平台限制记录

- **侧栏材质**：不用 Mica / 毛玻璃，三平台都用令牌里的纯色侧栏（浅色 Windows `#F3F3F3` / macOS `#ECECEC` / Linux `#F4F4F4`，深色 `#151517`）。理由：Mica 只在 Windows 11 生效，需要整窗透明，Windows 10 上会露底；开发机是 Windows 10，macOS 无真机，都没法验证。
- **macOS 红绿灯**：`tauri.macos.conf.json` 设 `titleBarStyle: Overlay`、`trafficLightPosition {18, 20}`，没有在 macOS 真机上看过位置；收起成图标栏时 Logo 行留空给红绿灯。
- **Windows 关闭键悬停**：沿用系统外观（红底白叉 `#C42B1C`），设计稿没画悬停态。
- **Cookie 登录小窗**：macOS 上窗口用 Overlay 标题栏 + 系统红绿灯（`cookie_login.rs`），红绿灯用默认位置（窗口构建接口没有设位置的方法）、标题让出左 80；没有 macOS 真机，未编译、未看过。
- （待实测：原生托盘菜单能否勾选后不关、Windows 默认项加粗、WebKit 毛玻璃。）
