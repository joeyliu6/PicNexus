# 设计没画、开发时补的（托盘）

> 读者：维护者，以及改托盘的 AI。阶段 8（T01–T08 K11）实施时按交接说明的规则自行补的做法；全部阶段做完后统一请维护者过目。原生菜单做不到的写法见 [README](../README.md)「平台限制记录」。

**点击与入口**
- Windows：左键单击或双击图标打开主界面，右键弹菜单；「打开 PicNexus」是菜单默认项（加粗）。左键若也弹菜单，双击的第二下会被菜单吃掉，「双击直接打开」就做不到。macOS 点图标弹菜单；Linux 由系统托盘决定，只能弹菜单。
- 托盘里的上传不打开主界面：在后台上传，状态行和托盘图标显示进度，结果由系统通知告知（主窗口隐藏或最小化时，所有普通通知都改走系统通知；带「撤销」的通知仍留在应用内）。全局快捷键与托盘走同一条上传路径，进度同样显示在托盘、首页「最近上传」和传输中心。
- 第一次启用公共图床（京东、七鱼）要确认风险：先打开主界面，再弹与首页相同的确认框。
- 前端画好菜单之前（启动时读配置那一两秒，或主窗口脚本出错时），托盘是只有「打开 PicNexus / 退出 PicNexus」的兜底菜单。

**菜单内容**
- 「上传到」当前值：一个都没选写「未选择」，选了一个写图床名，多个写「N 个图床」。子菜单与首页「上传到」同一份图床（已添加且已填好配置），末尾「管理图床…」打开图床页；一个都没有时只剩「管理图床…」。
- 子项的问题提示：Cookie 登录的图床写「登录失效」，点击打开登录窗口、不改勾选；其他图床写检测给出的原因（超过 16 字截断），点击照常切换。父项只在**勾选的**图床有问题时提示 ⚠。
- 「复制为」：四种格式 + 分隔线 +「自定义格式…」。点「自定义格式…」= 改用自定义格式并打开设置里的自定义模板；当前是自定义格式时它打勾，父项写「自定义」。在托盘改格式只改设置，不重新复制剪贴板里现有的内容（下一次上传才按新格式复制，T04）。
- 「压缩」：「关」+ 各压缩方案（单选）+ 分隔线 +「压缩设置与预览…」，与首页「压缩」菜单相同；父项写方案名或「关」。
- 三个勾选开关与设置页同一份配置、同一个保存入口；「全局快捷键」与设置页的开关同名（交接说明 9.5）。
- 快捷键提示写实际录的组合键；没设置的那项不写；关闭全局快捷键时全部不写（T07）。macOS 的「设置…」「退出 PicNexus」带 ⌘, / ⌘Q（设计稿），Linux 不带。
- 快捷键的写法：macOS / Linux 交给系统菜单按各自规矩画（⇧⌘C）；Windows 不用系统的快捷键栏，和右侧说明一起写进右列，中间空两格（「剪贴板无图片  Ctrl+Shift+C」）。录了系统菜单认不出的组合键时，菜单去掉快捷键照样建出来。
- 图床名、文件名里的「&」写成「&&」：三个平台的系统菜单都把「&」当快捷字母的标记。
- 从托盘或全局快捷键选文件上传，不出首页那条「更快的方法」提示（那条只给点首页按钮选文件的人）。
- 全局快捷键被别的程序占用时提示「全局快捷键未生效」+「Ctrl+Shift+C 已被其他程序占用，请在 设置 › 快捷键 中更换」（设计稿没画，同一组合键只提示一次）。

**上传中（T02）**
- 状态行：单张写「正在上传 文件名」+「已完成的图床数 / 图床数」（与传输中心的「1 / 3」同义）；多张写「正在上传 N 张」+「已传完的张数 / N」（失败的也算传完）。文件名超过 24 字从中间省略，留住扩展名。
- 托盘图标只画经典四瓣（16px 画不下 8 瓣）：1–4 个图床一瓣对一个图床，空槽按等待画；超过 4 个图床按落定的比例逐片点亮，下一片半亮。传完全亮、上传中半亮、等待暗；失败也算落定（单色小图分不出红，失败由系统通知说明）。上传中优先显示进度，不叠加「变淡」。多张时每瓣是该图床在整批上的情况，整批都落定才算这一瓣传完。
- 状态行前的小花瓣用首页花瓣同一套颜色（当前主题的令牌）。图床超过 8 个时只按比例画八瓣、不加数字（16px 的菜单图标放不下；交接说明规则 4.6 要加数字），总数由状态行右侧的「x / N」写出。

**托盘图标的颜色**
- Windows 按任务栏深浅（系统设置里「默认 Windows 模式」，不是应用模式）画深色或白色单色图标；切换深浅后，鼠标移到图标上或应用收到主题变化时重画。
- macOS 用模板图，由系统按菜单栏深浅上色。Linux 读不到面板颜色，固定画白色（GNOME 顶栏是深色）。

**剪贴板是否有图片**
- Windows：后台每 0.5 秒看一眼系统剪贴板序号（只读一个计数，几乎没有开销），一变就重查，打开菜单前就是对的；鼠标移到图标上时也会重查。只靠悬停不够：资源管理器转发托盘上的鼠标移动有延迟，移过去马上右键会看到上一次的状态。
- macOS：鼠标移到图标上时重查。Linux 收不到托盘悬停，第一项一直可点，剪贴板里没图片时点了由系统通知说明（沿用首页粘贴的说法「剪贴板里没有图片 / 复制一张图片后再按 Ctrl V」，托盘场景下后半句不太贴切，未单独改）。
- Windows 的剪贴板序号由托盘线程常驻看；「自动上传剪贴板」开着时它自己的线程也在看，两处各看一份，开销都可以忽略，不合并。

- 启动后、前端第一次画出花瓣之前（前端出错时会一直这样），托盘图标是彩色的应用图标；macOS 上这张图也标成了模板图，推断会显示成黑色剪影（没有真机）。
- 鼠标停在托盘图标上，提示文字固定是「PicNexus」，上传中也不写进度。Windows 单击图标只打开主界面，主界面开着时再点不会收起；「打开 PicNexus」停在上次看的那一页。
- 「退出 PicNexus」立即退出、不确认，正在上传也直接中断。
- 正在上传时「上传剪贴板图片」「选择文件上传…」仍可点，点了弹「请稍候」；「上传到」一个都没勾或没有图床时也可点，点了才用通知报错。剪贴板里是图片链接（文字）时第一项写「剪贴板无图片」、不可点（快捷键与首页粘贴会下载链接再上传，托盘这里更严）。
- Windows 读不到任务栏深浅时按深色任务栏画白色图标。
- 托盘里切三个开关不闪「已保存」，保存失败弹「未能保存」（主界面藏着时走系统通知）。
- 对已经传完的图片重试某个图床时，托盘没有状态行、图标不动（只看最新一批传没传完）。
- 第一次需要系统通知时才向系统要权限；用户拒绝后托盘发起的上传没有结果提示。点系统通知不会打开主界面。
- Cookie 图床出问题时托盘、首页、图床页一律说「登录失效」（首页设计稿写「登录已失效」，统一成短的、与状态词「失效」一致的说法）。
- 「登录失效」在原生菜单里与正文同色（系统菜单不能给单独一项上色，设计稿是琥珀色字）。
- 悬停刷新最多 0.8 秒一次。
- 子菜单里图床的问题原因用首页同一套说法（截到 16 个字），与图床页左栏的短标签不同。

**技术取舍**
- 菜单由主窗口前端用 Tauri 菜单接口画，配置在前端加密保存，Rust 读不到；托盘、首页、设置页因此在同一个页面里读写同一份配置，没有跨窗口缓存不同步的问题。
- 配置或进度一变就整份重建菜单（进度百分比不在菜单里，不会每帧重建）；换下来的菜单留 60 秒才释放，免得用户看着菜单时连着重建几次、把正在显示的那份销毁。点完一项后，配置没变的也再画一次，纠正系统菜单自己翻过去的勾（点已选中的格式、点「登录失效」的图床、取消风险确认）。
- Windows 加粗默认项要回到主线程拿菜单句柄：菜单正开着时会等它关上才生效，对下次打开起作用即可。
- 每次重建会在 Tauri 的菜单回调表里留下约 30 条不再用的记录（Tauri 不提供删除，退出应用即清空）。推算（未实测）：每条约 200 字节，一天重建几百次也只多占 1–2 MB，不处理。
