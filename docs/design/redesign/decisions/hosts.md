# 设计没画、开发时补的（图床）

> 读者：维护者，以及改这一页的 AI。阶段 6（P01–P16 K09）实施时按交接说明的规则自行补的做法；全部阶段做完后统一请维护者过目。入口见 [README](../README.md)。

**连接与断开**
- 连接 = 加进已添加**并启用**（刚接上就是要用它）；公共图床先过 P11。WebDAV / S3 新建的那份在「测试并连接」通过前只是页面里的草稿，关掉目录或换图床就丢弃；名字照「WebDAV 1」「S3 兼容存储 1」（现存最大序号 + 1），可点铅笔改（回车保存、Esc 取消，空名字或没改不保存）。
- 「测试并连接」时必填项没填：不发请求，那一格标红、红字「请填写 X」，结果条「X 未填写 · 请填写后再试」。
- 断开 = 从已添加、启用里去掉并清掉凭证，同时解除 Typora / Obsidian 对它的绑定，高级字段（自定义路径等）留着；不弹确认，通知「已断开 X / 已传的图片和链接不受影响」带倒计时「撤销」（按快照原样放回，含原来的位置）。它若是「复制」固定的图床，固定退回「最先完成」。WebDAV / S3 叫「删除这份…」，同样带撤销。断开最后一个也照常断开（一个都没有是正常状态：首页「没有图床」，图床页右侧直接是目录）。
- Cookie 图床的连接表单：没填 Cookie 时按钮「登录…」+「将在新窗口打开 X 官方登录页，登录后自动填入」；手动粘贴了 Cookie 后按钮改写「测试并连接」、不再开窗。会写入的图床写「将写入并删除一个测试文件」，京东 / 七鱼按钮叫「连接」。
- 进入图床页时，很早版本留下的单份「自定义 S3」（`services.custom_s3`）搬成一份多份配置（名字「自定义 S3」）：沿用旧设置页已有的迁移，只是挪到了图床页。

**字段与保存**
- 普通字段（已连接的图床）失焦且有改动即保存并自动测试一次；未连接的只改草稿。保存失败时红色通知「未能保存 / 原因，请重试」，界面不当作已保存。
- 敏感字段：点「查看」明文显示 30 秒；点「修改…」进入编辑，不输入就离开 = 取消，输入过又删空再离开 = 清空，先确认（「清空 X？ / 清空后需重新填写，否则无法上传到这个图床。」，红色「清空」）；查看失败通知「无法查看X / 请重新填写后再试」。Cookie 的密文前露出第一项的名字（「SUB=••••」，名字不是秘密），其余只有圆点。
- Cookie 字段：点进输入框即可粘贴，失焦保存并检测；字段旁（同一行）是「重新登录…」，打开官方登录页、登录后自动填入（登录过期时这个按钮挪到设置区最上面，字段旁不重复放）。字段下写「登录后自动填入，也可点击输入框粘贴」。不做「手动粘贴」按钮：它和点输入框效果相同，反而让人找不到自动登录的入口。
- 「HTTP · 已允许」只标后端真会放行的明文地址：对象存储是确认过的公开域名；WebDAV 是写成 IP 的局域网 / 本机地址、P12 确认过的、或已连接且最近一次没测失败的。已连接的图床填 http 公开地址时先保存再弹 P12，点「取消」地址仍留在配置里（不测，下次测试再问）。
- P12 代码框列出要放行的地址：对象存储是公开域名；WebDAV 是明文 HTTP 且写成主机名的那几个（IP 地址不用确认），一次确认对这份配置的两个地址都生效。
- 测试指到的字段收在「高级选项」里时自动展开；改那一格时保持展开。对象存储的「高级选项」摘要写实际收起的字段（R2 只有「自定义路径」）；WebDAV 的高级选项是「链接模板、防止图片互相覆盖」，开关写明代价。
- R2「使用第三方服务加速缩略图」沿用现有默认（开），P04 画的是关。

**测试结果**
- 结果条只在本次页面会话里保留；左栏的 ⚠ 来自持久的健康状态（上传失败也会让它变琥珀）。京东 / 七鱼的检测结果不写进健康状态。测试中左栏第二行写「检测中…」。
- 成功：三步的写「服务可用 · Nms · 读取、写入、公开访问均通过」，一步的写「凭证有效 / 登录有效」，京东 / 七鱼只写「服务可用 · Nms」。GitHub 测读取、写入两步，公开访问不测（CDN 缓存延迟）。
- 失败：标题「<字段名>无效」（中文字段名不加空格，英文的照常「Secret Access Key 无效」；指不到字段时写原因本身），后面接已通过的几步 + 处理办法（按这个图床表单上的叫法）；字段下面红字写原因。改了标红那一格后红框清掉、标题不变，直到下一次测试。不写设计稿的「其余各项均通过」：前一步没过时后面根本没测。
- 原因怎么说：R2 的 TLS 握手被拒指到 Account ID；没有存储桶权限不指字段，写「密钥没有访问这个存储桶的权限，请在 X 后台为它授予读写权限」；连不上 / 超时不指字段，写「无法连接存储服务（WebDAV 服务器），请检查网络后重试」；WebDAV 公开链接失败写「请检查公开访问地址和链接模板」。原始错误只进日志。
- 左栏与头部的问题短标签：Cookie 图床一律「登录失效」，凭证类「凭证无效」，公开链接类「公开链接异常」，其余「连接异常」（设计只画了前两种）。公开链接返回 403 算公开链接异常，不算凭证。

**列表、目录、使用情况**
- 左栏不画状态点，正常的不打标记、出问题才 ⚠（P01 说明开头写了「带状态点」，与同段后文和规则 4 冲突，照规则）。指针在清单里时先不重排，离开清单再按「有问题 → 已启用 → 停用」排（否则点「停用」后那一行立刻挪走，浮出的按钮落到另一个图床上）。右键菜单只有「启用 / 停用」。键盘：上下键、Home / End，整个清单只占一个 Tab 停留点。侧栏「图床」旁的琥珀点：已添加的图床有问题时出现。
- 「＋」在目录与连接表单里都保持按下的样子。一个图床都没有、或窄窗口时，目录不显示「关闭」。宽窗口下 Esc：连接表单回目录，目录回详情。目录搜索也搜「需要准备什么」那一行；没有结果写「没有符合条件的图床」。
- 「张最先完成」= 复制时使用的链接在这个图床上的张数；「张失效」= 复制时使用的那份在这个图床上且被查出失效的张数（与图库、链接健康同一口径），大于 0 时用琥珀色（设计稿画的红色，照规则 5：失效是需要留意的状态）并可点，跳到链接健康按这个图床筛选。
- 设计没画的图床照最接近的画法：对象存储照 R2、Token 照 GitHub、Cookie 照微博、免配置照京东、自定义 S3 照 WebDAV；知乎沿用现有开关 + 参数值。
- 微博链接前缀沿用出厂列表（搜狗图片等，第一项标「（默认）」），最前面加「不加前缀」；右下角写实际支持的变量「{url} {path} {url_encoded}」。GitHub「存储路径」帮助写「图片在仓库中的目录」、「分支」写「默认 main」；加速列表沿用现有数据，「原始地址」放最后；「添加 CDN」填整条地址模板。「添加模板… / 添加 CDN…」用弹窗（按钮带「…」，弹窗标题不带）；自己加的悬停可删、立即生效不撤销，出厂的不可删。

**Cookie 小窗与编辑器**
- 准备页 520×600（P16），点「开始登录」后放大到该网站登录页需要的尺寸；标题栏 40 高、侧栏底色，标题「微博登录」（照 CookieWindow.dc.html，不照交接说明 8.7 的「登录 微博」）；macOS 用系统红绿灯、不画关闭键。「开始登录」失败时原因写在按钮下方（不弹系统对话框）。登录成功通知「已登录 微博」；60 秒超时通知「微博登录超时」，处理办法指向图床页的「重新登录…」与直接粘贴 Cookie。
- 登录失效且图床停用时，头部「启用」是唯一的主按钮，「重新登录…」退为白色次要按钮（每页一个主按钮）。
- 会开新窗口或弹窗的按钮一律带「…」（交接说明 9.8，设计稿没加）：「登录…」「重新登录…」「添加模板…」「添加 CDN…」。
- 编辑器服务（Typora / Obsidian / CLI）的图床凭证由应用级同步从配置里取：启动时下发一次，之后每次配置变化重下发（`src/composables/settings/editorSync.ts`）。

- 窄窗口（< 1000px）一个图床都没有时，页面直接显示目录（不留一整页空白清单），没有「‹ 图床」；从目录点进连接表单后有「‹ 图床」回到目录。
