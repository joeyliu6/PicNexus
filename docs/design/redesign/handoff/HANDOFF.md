## 0. 先读这里

1. **以设计源文件为准。** `design-source/project/*.dc.html` 是每个界面的完整源码（布局、尺寸、颜色、文案、全部状态的数据）。本文解释「为什么这样」和「规则是什么」，数值冲突时以 `tokens/` 和源文件为准。

## 2. 设计原则

1. **内容是主角。** 界面只用灰阶退到后面；图片和链接才是页面上最显眼的东西。
2. **一种颜色一种意思。** 蓝 = 品牌与进行中；红 = 刚才的操作失败了；琥珀 = 需要留意的状态。不拿颜色做装饰。
3. **层级靠明度和留白。** 少画线、少套框。分组先拉开间距，再考虑底色，最后才用描边。
4. **同心圆角。** 内圆角 = 外圆角 − 内边距。
5. **状态双编码。** 颜色之外一定还有形状或文字；动效只用来解释因果，可以整体关掉。
6. **第一性原理。** 每个页面先问「用户点进来最需要什么」，只放那件事；不放多余信息、不在界面上常驻解释。

## 3. 平台与外壳

### 3.1 窗口结构

```
┌──────────┬──────────────────────────────────────────────┐
│ 侧栏 208 │ 标题栏行 40（窗口按钮在右上；macOS 红绿灯在侧栏左上）│
│ Logo 行52│ 页面标题行 46（标题 15/600，左距 24，与 Logo 行同中线）│
│ 搜索 32  │ 工具栏 / 状态栏 48                               │
│ 导航 32×n│ 内容区（铺满主窗口，内边距 24）                    │
│ …        │                                              │
│ 设置     │                                              │
└──────────┴──────────────────────────────────────────────┘
```

- **侧栏 208px**：Logo 行 52px（macOS 为红绿灯）→ 搜索框 32px（`Ctrl+K` / `⌘K` 打开命令面板）→ 导航：快传、图库、链接健康、图床；底部：设置。导航项高 32、圆角 8，当前页浅灰底 + 蓝色图标。
- **提示点**：链接健康有失效图片时侧栏项右侧一个 6px **琥珀色**点；有新版本时「设置」旁一个品牌蓝小点。不弹窗。
- **窄窗口**：宽度 < 1000px 自动收成 56px 图标栏（也可 `Ctrl+\` 手动），悬停出名字气泡。最小窗口 800×600，任何页面都不能出现横向滚动。
- **侧栏材质**：Windows 11 用 Mica；macOS 用毛玻璃（vibrancy）；Linux 用纯色。浅色侧栏底色分别为 `#F3F3F3 / #ECECEC / #F4F4F4`，深色统一 `#151517`。
- **窗口按钮**：Windows 46×40 方形三键（最小化 / 最大化 / 隐藏到托盘）；Linux 24px 圆形三键（GNOME 风格）；macOS 系统红绿灯。关闭按钮的语义是「隐藏到托盘」。

### 3.2 页面标题位置（统一规则）

- 双栏页（图床、设置）：标题在第二栏顶部 40px 行，与侧栏 Logo 行对齐。
- 单栏页（图库、链接健康）：标题在标题栏行左侧（左距 24，高 40，`margin-top: 6px`），与 Logo 行同一中线。
- 整个页面只有一个大标题；页面内不再出现第二个 20px 标题与它抢位置。

### 3.3 三平台差异只换这些

窗口按钮、侧栏材质、中文字体（Windows `Microsoft YaHei UI` / macOS `PingFang SC` / Linux `Noto Sans CJK SC`，西文统一 Inter）、快捷键写法（Windows / Linux `Ctrl+Shift+C`，macOS `⇧⌘C`）、托盘菜单的系统外观。**布局、结构、文案三个平台完全一致。**

### 3.4 焦点与键盘

Tab 顺序：侧栏 → 页面工具栏 → 内容 → 详情面板。焦点环统一品牌蓝 2px 外环。弹窗打开时焦点落在第一个输入框或主按钮，`Esc` 关闭。

## 4. 产品规则（硬约束）

1. **「上传到」**：勾选的图床**同时上传**，复制**最先完成**的链接（可在「复制」处固定某一个）。**不排序、不设主链接、不推荐图床。**
2. **图床只有「启用 / 停用」两种状态。** 图床页左栏不放开关，悬停时浮出「启用 / 停用」小按钮；详情头部只有一个状态按钮。首页「上传到」、托盘、图床页改的是同一份设置。
3. **每张图有一条「复制时使用」的链接**（「主链接」一词已废弃）。失效时可「改用」备份：**不弹确认，通知带撤销。**
4. **正常状态不打任何标记**（不放绿点、不放对勾）。只有出问题才显示：琥珀色 ⚠ + 原因。
5. **颜色分工**：红色 = 刚才的操作失败了（上传失败、写入失败）；琥珀色 = 需要留意的状态（失效、登录过期、可能受限）。
6. **花瓣**（品牌 Logo 的四瓣 = 图床）：1–4 个图床画四瓣，5–8 个画 N 瓣，超过 8 个画八瓣并加数字。几个图床传完亮几片；哪片变红就是哪个图床出了问题。
7. **背景装饰**：浅色用小花瓣光晕、深色用极光，**只用在首页（快传）和空状态**（图库无图、链接健康从未检测、引导欢迎页）。共用 `BgDecor` 组件。
8. **链接健康**：「修复」= 改用备份 + 更新「文档文件夹」中 Markdown 文档里的旧链接，不弹确认，通知带撤销；修改文档前自动备份原文件。文档修复、补充备份各是一个弹窗；补充备份只选目标图床，范围固定为「仅有 1 份的图片」。
9. **上传**：单张——第一个图床传完就复制，其余图床后台继续；多张——整批结束后一次复制全部成功的链接（每行一个，按拖入顺序），每张至少传上一个图床才算成功；某个图床整批失败只报一行。
10. **设置改动即保存**，没有「保存」按钮；成功只在改动处短暂显示「已保存」。

| 琥珀（需要留意）文字 / 填充 / 浅底 | `warning…` | `#AD4F08 / #D97706 / #FEF4E6` | `#F2B35C / #F59E0B / #2E2414` |
| 红（操作失败）文字 / 填充 / 浅底 | `danger…` | `#B91C1C / #DC2626 / #FDECEC` | `#FF7A7A / #EF4444 / #33191A` |

- 所有文字与背景对比度 ≥ 4.5:1（禁用文字除外）。浅色下「成功绿 / 警示橙」文字色已调成 `#147A3A / #AD4F08`，在 macOS 侧栏上也达标。
- **深色模式**目标：图片是主角、界面退后、不刺眼。背景中性灰不偏色；层级「越靠上越亮」：侧栏 `#151517` < 页面 `#1C1C1E` < 卡片 `#2A2A2D` < 菜单 `#36363A`；深色下阴影看不见，浮层用 1px 8–10% 白描边代替。缩略图加 1px 浅描边。
- 大数字一律千分位（12,483）。

### 5.2 字体与字号

- 字号只用：**20/26**（全应用最大，页结论 / 设置页标题）、**17/24**（对话框标题）、**15/22**（页面标题、分组标题）、**13/20**（正文基准）、**12/16**（说明、脚注）、**11/14**（标注、坐标轴）；等宽 12/18（链接、路径，JetBrains Mono）。
- 字重只用 400 / 500 / 600。

### 5.3 间距、圆角、层级、动效

- 间距：2 / 4 / 6 / 8 / 12 / 16 / 20 / 24 / 32 / 56。
- 圆角：4（快捷键、小标签）/ 6（小按钮、菜单项）/ 8（按钮、输入框、导航项）/ 10（列表行、缩略图）/ 14（投放区、弹出层、通知）/ 16（对话框、工具卡）/ 20（大面板）。
- 层级：e1 贴面（缩略图）/ e2 卡片（焦点卡，带一点品牌蓝）/ e3 浮层（菜单、下拉）/ e4 对话（对话框、命令面板）。**只有浮起来的东西才有阴影。**
- 动效：即时 100ms（悬停）/ 快 150ms（复制→已复制、开关）/ 标准 200ms（菜单出现）/ 舒展 250ms（对话框、抽屉、灯箱）；进场 `cubic-bezier(.2,0,0,1)`，退场 `(.4,0,1,1)` 且快 30%。系统「减少动态效果」开启时，位移改淡入，花瓣停止闪烁。

### 5.4 少用描边（规则 ⑨）

面板用浅灰底面（`surface`）区分层次；列表不套框，只在行与行之间留一条从文字处开始的细线；次要按钮用**白色浮起按钮**（白底 + `0 0 0 0.5px rgba(0,0,0,.06), 0 1px 2px rgba(0,0,0,.08)`，深色为 `#36363A` 无阴影）。工具入口用**小插画**（文档、花瓣、划掉的图、表盘），不用「渐变底 + 线条图标」的图标块。

> 说明：图库、图床、设置等较早定稿的页面里仍有描边卡片与描边按钮，属于已验收的样式，按源文件实现即可；新写的面板按本条执行。

## 8. 页面说明

逐张状态的细节在 `states/STATES.md` 的「设计说明」列（即画布注释原文）。这里讲结构与关键交互。

### 8.1 首页·快传（HomeScreen）
- **核心**：拖入 / 粘贴（`Ctrl+V`）/ 选择文件 / 从 URL 下载 → 上传到勾选的图床 → 自动复制链接。
- **焦点卡**：显示刚上传的图，花瓣逐个点亮；第一个图床完成 → 链接出现、自动复制，卡片变「已复制 · Markdown」。这个标签同时是格式开关，点它换格式再复制。下一张上传后，这张收进「最近上传」列表。
- **部分失败**：链接照常来自最先成功的图床；失败图床的花瓣变红，一行写原因 + 两个下一步（如「重新登录」打开 Cookie 登录窗，成功后自动重试）。**全部失败**：不显示链接，并明说剪贴板没有变。
- **批量（30 张）**：每张一块缩略图（完成 / 进度环 / 等待中变灰），同时传 3 张；整批结束前不动剪贴板；结束后一次复制全部成功链接；「重试这 2 张」只重传失败的。
- **拖放悬停**：任何页面都出现遮罩，侧栏保持可见；非图片文件提前说明会被跳过；`Esc` 或拖出窗口取消。
- **「上传到」浮层**：图床做成轻量标签，点选多选；已选浅蓝底蓝字带对勾，未选浅灰；异常图床名后琥珀小点 + 下方一行原因与「重新登录」；底部「复制 最先完成的链接 ▾」和「管理图床 ›」。图床很多（16 个）时：已选的排最前（面板打开期间不跳动），超过 6 个顶部出现搜索，标签区固定高度内部滚动，标题旁「已选 4 / 16」。
- **「复制为」菜单**：只列格式名（URL / Markdown / HTML / BBCode / 自定义），选中即改默认格式并重新复制焦点卡链接。**「压缩」菜单**：方案名 + 一行参数，「关」= 原图。
- **传输中心**：标题栏传输图标打开；上传 / 补充备份 / 链接检测分组；盖在内容上方不挤压布局。
- **命令面板**（`Ctrl+K` / `⌘K`）：空输入给最近 3 张、常用跳转与动作；输入时按文件名实时匹配（命中字蓝色）；图片 `Enter` 复制链接（面板不关，行内显示「已复制」），`Ctrl+Enter` 在图库中定位；设置项 `Enter` 跳转并高亮 1 秒。
- **渐进提示**：用户第一次点按钮选文件后，轻提示更快的方法（只出现一次，「知道了」或 8 秒后消失）。
- **第一次使用 / 没有图床**：投放区放大居中 + 三条上传方式说明；只有京东（已选）和七鱼两个免配置图床可一键加上做备份；没有可用图床时拖入遮罩写「先启用一个图床」。

### 8.2 图库（GalleryScreen）
- **网格**：按天分组、等高行、宽度按原比例（截图不裁切）；日期标题滚动吸顶。悬停：左上选择框、右上收藏、左下花瓣（几份备份）、右下「复制」。常驻角标只在需要注意时出现：⚠ 失效 / ⚠ 可能受限 / 仅 1 份（深色半透明小牌）。单击 → 右侧详情（宽 340）；双击或空格 → 灯箱；方向键移动。
- **时间刻度条**：一块毛玻璃（半透明 + 背景虚化）浮在图片右缘，图片铺满宽度；滚动或鼠标靠近右缘时出现，停止 1.5 秒后淡出；拖动跳年月，悬停出同样毛玻璃的「2026 年 10 月」。
- **多选**：点选择框 / `Ctrl`·`⌘` 单击 / `Shift` 连选 / `Ctrl`·`⌘ A`。选中的图在自己的格子里**缩小到 86%**，露出浅蓝底，左上角蓝色圆形对勾，**不向外扩边**；未选中的图常驻空心圆圈。底部浮出操作条。复制回执「已复制 12 张」（有跳过写「已复制 10 张（2 张没有可用链接）」）。`Esc` 取消。
- **列表视图**：缩略图 · 文件名 · 图床（花瓣 + 名称）· 尺寸与大小 · 上传时间 · 状态 · 操作；「状态」列平时为空。行高 54，虚拟滚动。
- **筛选**：条件显示为可单独移除的小标签 +「清除全部」；生效的筛选按钮变实底并写出取值；计数从「共 12,483 张」变「找到 4 张」。
- **详情**：从上到下只有三件事：图 → 链接（一键复制）→ 存放在哪几个图床（每个一行；「复制时使用」那一个有标注；失效的琥珀色「⚠ 图片已不存在」）。出问题时顶部一条琥珀提示 + 唯一主按钮「改用京东」（立即生效，通知带撤销）。「补充备份到…」列出还没有这张图的图床。全部失效时说清下一步；「移除记录」只放底部。
- **灯箱**：从缩略图位置放大，`Esc` 缩回；← → 切换、滚轮缩放、拖动平移；当前图床加载失败时顶部提示 +「换个图床」。
- **空状态**：无图（带背景装饰，「前往快传」）/ 筛选无结果（保留筛选标签 +「清除筛选」）/ 收藏为空（只说明怎么收藏，不放按钮）。
- **冷启动**：超过 300ms 才出骨架，按「日期标题 + 等高行」排；缩略图加载失败先自动换其他备份地址。

### 8.3 链接健康（HealthScreen）— 本轮重点

**用户来这里只为三件事**：有没有坏图 → 一键修好（包括已写进文章里的链接）→ 以后少坏。

**版式（从上到下）**：标题行「链接健康」→ **状态栏**（48 内，一句状态 + 操作）→ **上传日历面板** → **三张工具卡** → **全部失效图片**。没有二级页面；文档修复、补充备份是弹窗。

**状态栏**（与图库工具栏同级，13px）
- 有问题：琥珀色 7px 圆点 + 「21 张图片失效」（600）+ 一句说明（集中在哪些年份 / 哪个图床 · 可修复几张 · 可能受限几张）；右侧「重新检测」（白色浮起按钮）+「修复 15 张」（**全页唯一主按钮**）+「⋯」。
- 检测中：转圈 + 「正在检测」+「1,024 / 3,500 · 等待微博响应 · 已发现 3 张失效」+ 120px 细进度条 +「暂停」。暂停：暂停符号、进度条变灰、「取消 / 继续」。
- 修复中：转圈 +「正在修复」+「9 / 15 · 同时更新 3 个文档中的旧链接」+ 进度条。
- 全部正常：「全部正常」+「12,483 张图片均可访问 · 上次检测：3 天前」，**不加对勾或绿色**。
- 尚未检测：「尚未检测」+「共 12,483 张图片 · 只读操作，约需 15 分钟」+ 主按钮「开始检测」。
- 「⋯」菜单：仅重新检测 N 张失效图片 / 导出结果（CSV）/ 自动检测（每 7 天 ›）/ 分隔 / 红字「清理找不回的图片…」+ 说明「只含『图片已不存在』的 N 张，不含超时与拒绝访问」。

**上传日历**（参考 GitHub 提交图，`surface` 浅灰面板、圆角 20、无描边）
- 一次看**一年**：7 行（周一到周日，左侧只标「一 三 五」）× 53 列，**一格 = 一天**。格子 13px、间距 3、圆角 3.5；上方月份标签 11px。
- 颜色：空 `cellEmpty`；当天上传量按 4 档蓝（`cellLv1–4`）；**当天上传的图里有失效**的格子变琥珀：1 张浅（`cellBadSoft`），2 张及以上深（`cellBad`）。未来日期透明。
- **图上不放图例、说明文字和悬停示意**；悬停 / 点击是交互，不是界面上的文字。
- 年份切换：面板顶部一排胶囊按钮，**最近 6 年平铺**，其余收进「更早 ▾」；有失效的年份按钮旁用 11px 琥珀数字写张数（「更早」写合计）。选中的年份是白色浮起胶囊。右侧一行灰字「2023 年上传 1,987 张 · 4 张失效」。
- 默认选中：**最近一个有失效图片的年份**；没有问题时选**今年**。
- 点击某一天：该格加深色外圈（`0 0 0 2px surface, 0 0 0 3.5px text1`），下方清单筛到当天，并在清单标题旁出现可移除的日期标签「2023年5月22日 ×」。
- 检测中：发现一张就点亮一格。修复后：修好的格子变回蓝色。

**三张工具卡**（3 列等宽，`surface` 底、圆角 16、无描边；左插画 60×52 → 标题 + 数量 → 一句说明 → 右侧白色浮起按钮）
- 文档修复：「3 个文档 · 4 处失效图片可替换为备份」→「修复文档…」；未添加文件夹时「添加文件夹…」；全部正常时「97 个文档 · 均无失效图片」→「管理文件夹…」；修复后「3 个文档已更新 · 共替换 7 处旧链接，可撤销」。
- 补充备份：「1,206 张 · 仅保存在 1 个图床，图床失效后无法恢复」→「补充备份…」；进行中显示「96 / 1,206」+ 细进度条 +「暂停」；完成「已完成 · 每张图片至少保存在 2 个图床」（无按钮）；只有一个可用图床时按钮换「添加图床」。
- 第三张：有问题时是「找不回的图片 · 6 张」（数字琥珀）→「查看」；没有问题时是「自动检测 · 每 7 天 · 下次检测：10月19日」→「更改」（尚未检测时「开启」）。

**全部失效图片**
- 标题「全部失效图片 · 21 张」，**不受日历年份影响**——这是「一次找全、一次修完」的入口。右侧三个筛选：原因（图片已不存在 / 拒绝访问 / 连接超时 / 可能受限）、图床、年份；年份菜单只列有失效的年份并带张数，最后一项「与上方日历同步」。
- 分两组：「可改用备份 15 张」「无可用备份 6 张」，每组先显示 3 / 2 行 +「显示其余 N 张」。
- 行（最小高 56，不套框，行间细线从缩略图右侧开始）：40px 缩略图 · 文件名 + 「原因（琥珀）· 备份情况（灰）」· 上传日期 · 「用于 N 个文档」· 操作（「改用京东」/「重试」）· 「⋯」。
- 行「⋯」菜单：重新检测这张 / 重新上传原图… / 在图库中查看 / 在浏览器打开 / 分隔 / 红字「移除失效链接…」（执行前再确认，提醒文档中可能仍有引用）。
- 单行重试结果没变化：按钮位置停 2 秒显示琥珀「仍然失效」，再恢复成「重试」，不弹通知。
- 修复中：每行右侧写「已改用京东 / 正在修复… / 等待中」。
- 检测中：标题改「已发现的失效图片」，边查边出现。全部正常 / 尚未检测：不显示清单。

**修复的语义**
- 「修复 N 张」/ 行内「改用 X」= 把这张图的「复制时使用」切到一个可访问的备份 **并** 替换文档文件夹中所有 Markdown 里的旧链接。不弹确认。
- 完成通知：成功「已修复 15 张图片 · 已更新 3 个文档中的 7 处旧链接」+「撤销」（倒计时）；部分失败另起一条红色通知「1 个文档未能更新 · README.md 被其他程序占用，请关闭后重试」+「重试」（只重试没写入的文档）。

**弹窗**（统一对话框规格）
- 文档修复：上半「文档文件夹」列表（路径等宽字 + 文档数 + 移除 ×，「＋ 添加文件夹…」）；下半「需要修复的文档 · 3 个文档 · 5 处失效」（文件名、所在目录、几处失效几处可替换、用编辑器打开）；脚注「修改前自动备份原文件，可撤销。无可用备份的 1 处保持原样。」；「取消 / 修复 4 处」。
- 补充备份：「1,206 张图片仅有 1 份」；只问「复制到」哪个图床（单选，每行 HostIcon + 名称 + 已有张数；登录过期的变淡并写原因，不可选）；脚注「预计 18 分钟，在后台进行；进度显示在本页和传输中心。」；「取消 / 开始备份」。

**窄窗口 800×600**：日历格子缩到 9px、间距 2，月份只标单数月；工具卡去掉插画、按钮移到说明下方；清单隐藏日期和文档两列，隐藏筛选按钮；年份汇总文字隐藏。

### 8.4 图床（HostsScreen）
- 双栏：左栏只列**已添加**的图床（标题「图床」+「＋」在左栏顶部，分隔线贯穿到底）；右侧详情限宽居中。
- 左栏排序固定：有问题的 → 已启用的 → 停用的。停用整行变淡、第二行「已停用」；有问题的第二行琥珀「⚠ 登录失效」。正常时左栏干干净净，**不放开关**；悬停一行右侧浮出「启用 / 停用」小按钮（也可右键或空格）。
- 详情头部：名称 + 说明 + 检测按钮 + **一个**状态按钮（启用时浅蓝「✓ 已启用」点一下停用；停用时蓝色实心「启用」）。下面：使用情况（三个数字 + 近 14 天上传总数 + 柱状图）→ 设置 → 断开连接。
- 各类接入：京东免配置；微博 Cookie 登录（异常时「重新登录」放最上面，打开独立 Cookie 登录小窗）+ 链接前缀模板（单选、带预览、可增删）；GitHub Token（「去 GitHub 生成」打开带好权限的页面）+ CDN 模板；Cloudflare R2 对象存储（高级选项收起；缩略图加速写明代价）；WebDAV 可多份、可重命名，局域网 HTTP 标「HTTP · 已允许」。
- 测试连接：按钮原地「正在检测…」，依次测 凭证 → 写入 → 公开访问；成功结果条写清通过了哪几项（不弹通知）；失败指到具体字段（那一格变红 + 原因）。
- 敏感字段：默认密文，「查看」显示明文 30 秒后自动收回；点进字段即清空等待粘贴（旧值不回显），离开即保存并自动测试。
- 弹窗：公共图床风险确认（「我已了解并继续」，确认一次不再问）；明文 HTTP 域名确认（只对该地址生效）。
- 添加图床：右侧换成目录，搜索 + 接入方式筛选，按方式分组三列卡片。
- 窄窗口：两级——清单 → 详情（左上「‹ 图床」返回，`Esc` / `Alt+←`）。

### 8.5 设置（SettingsScreen）
- 7 个分组：通用、上传与链接、快捷键、编辑器与命令行、备份与同步、数据与隐私、关于。
- 每页同一结构：标题 20/26 + 一句说明 → 分组小标题（12px、600、次要色）→ 分组卡片（每行 ≥ 48 高，左名称 + 一句说明，右控件）→ 卡片下方灰色脚注说清后果。二级栏顶部是「设置」标题，**不放搜索框**（命令面板能搜到每一项）。
- 快捷键：可整体关闭；点组合键进入录制（「按下新的组合键…」，`Esc` 取消、`Backspace` 清除）；冲突时不保存，红框 + 说清被谁占用。
- 备份与同步：一张「云同步」卡（顶部状态 + 一个「同步」按钮，危险的「覆盖云端 / 覆盖本地」收进「⋯」）；同步中 / 成功 / 失败都写在状态行，不弹通知；覆盖本地必须确认；云端配置下载后常驻刷新横幅（与内容同宽）。未设置备份密码时导出会提示先设置密码。
- 数据与隐私：不能撤销的操作单独成组，标题就写「不能撤销」，红字按钮 + 省略号。
- 关于 / 更新：有新版本时侧栏「设置」和「关于」各一个小圆点，不弹窗；更新卡片 7 种状态（检查中、已是最新、发现新版本、下载中、正在安装、已安装重启完成、失败），重启前会等正在进行的上传传完。

### 8.6 托盘（TrayWindow）
- 点托盘图标是**系统原生菜单**（不是浮窗）。只做一件事：不打开主界面就能改「怎么传」。
- 结构：上传剪贴板图片 / 选择文件上传… → 分隔 → 上传到（当前值「3 个图床」）/ 复制为（「Markdown」）/ 压缩（「Web」）→ 分隔 → 勾选：自动复制链接、自动上传剪贴板、全局快捷键 → 分隔 → 打开 PicNexus（Windows 加粗、双击图标直接打开）/ 设置… / 退出 PicNexus。**不放图片和历史。**
- 上传中：顶部多一条不可点的状态行（花瓣 + 文件名 + 1 / 3 + 细进度条），托盘图标花瓣按进度逐片点亮。
- 「上传到」子菜单多选、勾选即生效、菜单不关；登录失效的父项旁琥珀小点，子项写「登录失效」。「复制为」单选，右侧用等宽字写出格式样子。
- 剪贴板无图片：第一项变灰并注明原因。关闭全局快捷键：快捷键提示消失，托盘图标整体变淡。
- 平台：Windows 行高 32；macOS 行高 24、强调色整行高亮、⇧⌘ 符号；GNOME 行高 32。

### 8.7 新手引导、弹窗、通知
- 引导 3 步：欢迎（一张图讲清「一张图 → 三个图床，坏了一份就改用另一份」，只有「下一步」和「跳过」）→ 选图床（京东默认勾选并视为确认风险说明）→ 怎么传（四种上传方式 + 选默认格式），「开始使用」落到首页；可在 设置 › 关于 重新打开。
- 启动还原备份配置（阻塞弹窗）、密码错误（写剩余次数）、设置 / 修改 / 关闭备份密码：见 `Dialogs.dc.html`。
- Cookie 登录小窗：独立窗口 520×600，自绘标题栏「登录 微博」；「开始登录」后下方换成网站登录页，成功自动关闭，主窗口通知「已登录 微博」。

## 9. 文案规范

1. 书面、简洁，像系统设置：「自动复制链接」，不写「上传后自动复制链接」。
2. 设置项用名词或动宾短语，4–7 字；说明行一句话，不用口头语（不用、就、一下、还是、能…）。
3. 状态用固定词：**正常 / 失效 / 可能受限 / 等待中 / 上传中 / 已完成**。不用「打不开」「能打开」。
4. 错误 = 原因 + 处理办法：「无法连接 GitHub，请稍后重试」。
5. 同一功能在首页、托盘、设置里同名：上传剪贴板图片、选择文件上传、自动复制链接、自动上传剪贴板、全局快捷键。
6. 数字与单位间留空格：「21 张」「18 MB」；大数字千分位；macOS 快捷键按系统顺序写 ⇧⌘C。
7. 颜色只表达两种问题：红 = 刚才的操作失败了；琥珀 ⚠ = 需要留意的状态。正常状态不打任何标记。
8. 会再确认的危险操作在按钮文字后加省略号「…」；打开新窗口 / 弹窗的按钮也加「…」。

## 10. 动效（Logo 花瓣）

八个方向见 `M01–M08`（画板默认深色）。原则：每个动效对应一个真实时刻；花瓣 = 图床；反馈类 ≤ 0.6 秒，状态类慢速循环 2.4–3.6 秒，启动只播一次；「减少动态效果」时全部静态；光粒子、发光只在深色背景和启动画面用。**建议优先落地 ③ 花瓣逐片点亮（上传进度）、⑥ 完成绽放（已复制）、⑦ 拖入感应**；① 光粒子汇聚、④ 分发粒子用在启动和引导。

## 13. 技术落地建议（Tauri 2 + Vue 3）

以下是建议，不是设计硬约束；以现有代码结构为准时请保持视觉与交互一致。

### 13.1 主题与平台
- 把 `tokens/tokens.css` 放进全局样式；根元素设 `data-theme="light|dark"`（跟随系统，可在设置 › 通用覆盖）和 `data-platform="windows|macos|linux"`（启动时由 Tauri `os` 插件判定）。
- 组件只引用 `var(--pn-*)`，不写死颜色。

### 13.2 建议目录
```
src/
  styles/tokens.css
  shell/        AppShell.vue  Sidebar.vue  NavRail.vue  TitleBar.vue  WindowControls.vue  CommandPalette.vue  TransferCenter.vue
  components/   PnButton  PnSoftButton  PnInput  PnSwitch  PnCheckbox  PnRadio  PnSelect  PnSegmented  PnMenu  PnTooltip  PnPopover
                PnDialog  PnToast(+useToast)  PnSkeleton  PnEmpty
  biz/          HostIcon  Petals  ThumbCard  LinkBlock  CopyButton  BgDecor  ToolCard(+插画)  UploadCalendar  YearPills
  views/        Home  Gallery  Health  Hosts  Settings
  windows/      CookieLogin  Onboarding
```

### 13.3 Tauri 能力对应
- 窗口：Windows / Linux 关闭系统装饰、自绘标题栏（`decorations: false` + `data-tauri-drag-region`）；macOS 用 `titleBarStyle: "Overlay"` 保留红绿灯。Windows Mica / macOS 毛玻璃可用 `window-vibrancy`。关闭 = 隐藏到托盘。
- 托盘：用 Tauri 原生托盘菜单（`tray` + `menu`，含 `CheckMenuItem`、子菜单），**不要做成 WebView 浮窗**；图标需要可切换的模板图（上传进度逐片点亮、暂停时变淡）。
- 全局快捷键：`global-shortcut`；剪贴板：`clipboard-manager`；系统通知：`notification`（托盘上传完成）；更新：`updater`；文件夹选择：`dialog`；文档修复读写：`fs`（仅限用户添加的文档文件夹）。
- 窄窗口：用窗口宽度（或容器查询）切换 `size` 档位：< 1000px 收侧栏；最小窗口 800×600。

### 13.4 链接健康需要的数据
```ts
Image   { id, name, width, height, bytes, uploadedAt, favorite,
          copies: Copy[], useCopyHostId,         // 「复制时使用」
          docRefs: { path, line }[] }            // 文档文件夹扫描所得
Copy    { hostId, url, status: 'ok'|'gone'|'denied'|'timeout'|'limited'|'unchecked', checkedAt, latencyMs }
```
- **失效图片** = `useCopyHostId` 那份不可访问（`gone / denied / timeout`）。**可改用备份** = 还有 `ok` 的副本；**无可用备份** = 一份都没有。**可能受限** = `limited`（浏览器可见、外站引用可能失败），单独计数，不算失效。
- **仅有 1 份** = `ok` 副本数为 1（已失效的备份不算），这正是补充备份的范围，所以不需要「只补已失效的备份」之类选项。
- **改用哪一份**：在可访问的副本里取最近一次检测响应最快的（不引入任何图床排序或推荐概念）。
- **日历**：按 `uploadedAt` 的本地日期聚合每日上传数与失效数；上传量 4 档按当年非零日的分位数划分。
- **文档修复**：扫描文档文件夹中的 `.md`，把旧 URL 替换为新 URL；写入前把原文件备份到 `<文件夹>/.picnexus-backup/<时间戳>/`；撤销 = 还原备份并恢复 `useCopyHostId`。写入失败要给出具体原因（被占用 / 没有写入权限 / 文件找不到了）。
- **检测**：只读请求，可暂停 / 继续（从中断处继续）；进度要能显示「等待某图床响应」。

### 13.5 原型
`Prototype.dc.html` 是一个可点击的核心流程原型：拖入上传 → 已复制 → 命令面板搜索旧图 → 详情改用备份 → 通知撤销。可在画布上点 ▶ 体验，用来对照实现的手感。
