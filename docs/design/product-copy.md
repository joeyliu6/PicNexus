# 产品文案

> 文案以设计稿为准：界面上写的字逐字照 `design-source/project/*.dc.html`；设计稿没写到的地方按下面的规则写，并记进对应页面的 [decisions/](./redesign/decisions/)。规则来自交接说明第 9 节。

## 规则

1. **书面、简洁**，像系统设置：「自动复制链接」，不写「上传后自动复制链接」。不用口头语（不用、就、一下、还是、能、打不开）。
2. **设置项**用名词或动宾短语，4–7 字；说明行一句话。
3. **状态固定词**：正常 / 失效 / 可能受限 / 等待中 / 上传中 / 已完成。成功写「已 + 动词」（已上传、已同步、已改用备份），失败写「XX 失败」或「未能 XX」。
4. **错误 = 原因 + 处理办法**：「无法连接 GitHub，请稍后重试」。处理办法指向此刻点得到的地方：凭证、登录、测试连接、添加图床在图床页；格式、快捷键、同步、编辑器在设置；失败的图片在首页重试。认不出的原因保留原文，不编。
5. **同一功能在首页、托盘、设置里同名**：上传剪贴板图片、选择文件上传、自动复制链接、自动上传剪贴板、全局快捷键。给用户看的文案若在 Rust 与前端各写一份，登记进 `scripts/check-cross-language-constants.mjs` 的 `PAIRS`。
6. **数字**：与单位间留空格（「21 张」「18 MB」），大数字千分位（12,483），文件大小 KB 取整、MB / GB 小于 10 留一位小数（`formatFileSize`）。
7. **快捷键写法按平台**：Windows / Linux `Ctrl+Shift+C`，macOS `⇧⌘C`（`PnKbd` 与 `formatShortcut` 负责）。
8. **颜色只表达两种问题**：红 = 刚才的操作失败了；琥珀 ⚠ = 需要留意的状态。正常状态不打任何标记。
9. **「…」**：会再确认的危险操作、会打开新窗口 / 弹窗 / 系统文件窗口的按钮，文字后加「…」，设计稿漏加的也加（「重新登录…」「添加模板…」「编辑…」「设置密码…」等）；弹窗标题不加。
10. **危险按钮写动作**（「清空」「覆盖本地」「关闭密码」），不写「确定」「继续」；确认框正文写「会发生什么 + 能不能撤销」。
11. 「复制时使用」不叫「主链接」；图床只有「启用 / 停用」，不说「参与上传」。

## 文案放在哪

- 多处复用的通知文案：`src/constants/toastMessages.ts`；确认框默认按钮字：`src/constants/uiCopy.ts`。
- 上传失败原因的固定说法：`src/utils/uploadFailureMessage.ts`（`describeUploadFailure`）。
- 只在一个组件里出现的文案直接写在组件里，长句用函数模板，不在模板里拼。
- 通知的通道与写法见 [notification-patterns.md](./notification-patterns.md)。
